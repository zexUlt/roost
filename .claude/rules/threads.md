# Код в нескольких потоках и ThreadSanitizer

Qt собран без инструментации: синхронизацию внутри QtCore и QtQuick (очередь событий, `QMutex`, sync сцены) TSan не видит. Передача данных между потоками через Qt для него выглядит гонкой. Поэтому передавать данные между потоками можно только так, как описано ниже.

## Как передавать данные между потоками

- В IO-поток — только через `IoThread::Post`. Задачи идут через очередь под `std::mutex`, а Qt лишь будит поток вызовом без данных. Лямбду с захватами через `QMetaObject::invokeMethod` или queued-соединение в другой поток не отправлять.
- Свой поток — с синхронизацией на std-примитивах (`std::mutex`, `std::atomic`), которые TSan видит. Qt-примитивы (`QMutex`, `QReadWriteLock`, `QWaitCondition`) для данных, общих между потоками roost, не брать.
- `TerminalItem`: всё, что читает `updatePaintNode`, пишется в GUI-потоке, и после записи кадр запрашивается через `requestRender()`, а не голым `update()`. Новый item со своим `updatePaintNode` повторяет ту же пару `TsanRelease` → `TsanAcquire`.

## Аннотации и suppressions

- `TsanRelease` и `TsanAcquire` (`src/core/tsan.hpp`) утверждают порядок, который гарантирует Qt, но не видит TSan. Ставятся только там, где эту гарантию можно назвать: функция Qt и её документированный контракт — в комментарии рядом. Заглушить отчёт аннотацией без такой гарантии нельзя: это прячет настоящую гонку.
- `tests/tsan.supp` — только кадры внутри Qt, которые не оборачивают код roost. Функции roost туда не попадают никогда. У каждой строки — комментарий: какой отчёт и на какую гарантию Qt опирается. TSan сверяет шаблон с каждым кадром обоих стеков, поэтому шаблон уже, чем кажется, не бывает: проверяй, что он не совпадёт с кадром roost.
- Новый отчёт TSan сначала разбирается по стекам: если порядок задаёт код roost, это настоящая гонка, и правится код, а не suppression.

## Тесты

- Тест кода, работающего в нескольких потоках, получает метку `threads` в `tests/CMakeLists.txt`: пресет `tsan` гоняет только их, с `QSG_RENDER_LOOP=threaded`.
- Санитайзеры гоняются только в CI. Локально — dev-сборка, тесты с меткой `threads` под `QSG_RENDER_LOOP=threaded`.
- CI-лог tsan читать целиком: `halt_on_error=0`, один прогон показывает все отчёты. Сгруппировать по `SUMMARY:` и тесту, потом читать стеки.
