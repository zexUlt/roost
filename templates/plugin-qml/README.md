# Шаблон QML-плагина

Плагин с одной панелью на QML и без бэкенда. Окно грузит панель с диска, шаг сборки не нужен.

## Как сделать плагин

1. Скопируй каталог `templates/plugin-qml` под любым именем: имя каталога ни на что не влияет.
2. В `plugin.json` смени `id`. Он задаётся только здесь: QML получает его от окна через свойство `pluginId` корня панели. Допустимы строчные буквы, цифры, `.`, `_` и `-`, начинается с буквы или цифры; `keymap` зарезервирован.
3. В `plugin.json` смени `id` панели (`contributes.panels[0].id`). Это глобальное имя панели, оно должно быть уникальным среди всех плагинов; принято начинать его с id плагина.
4. Положи каталог в `<каталог состояния>/plugins`. Каталог состояния — `$ROOST_CONFIG`, иначе `$XDG_CONFIG_HOME/roost`, иначе `~/.config/roost`. Для проверки без правки состояния укажи каталог через `ROOST_PLUGINS_PATH=<абсолютный путь>` (несколько — через `:`).
5. Перезапусти `roostd`. Плагин должен быть в ответе `plugins.list` без записей в `problems`.
6. Правь `qml/HelloPanel.qml`. С `roost --dev` окно перезагружает панель при изменении файла.

Корень панели — `Item`; необязательное свойство `pluginId` получает id плагина. Входы и выходы панели объявляются в `inputs` и `outputs` манифеста и должны быть свойствами корня. API — синглтон `Roost` из `import Roost.Api`.

## Как добавить бэкенд

1. Положи исполняемый файл в `backend/` плагина. Язык любой, протокол — JSON-RPC 2.0 по stdio, одно сообщение на строку.
2. В `plugin.json` добавь рядом с `contributes`:
   `"backend": { "command": ["backend/run"] }`
   Путь — внутри каталога плагина; бэкенд запускается в нём.
3. В `contributes` объяви команды:
   `"commands": [{ "id": "<id>.doThing", "title": "Do the thing" }]`
4. Бэкенд отвечает на запрос `commands.run` с параметрами `{command, args}`: в `result` кладёт ответ, неизвестную команду отвергает ошибкой `-32602`. Закрытый stdin значит «завершись».
5. Из QML команду зовёт `Roost.commands.run("<id>.doThing", args, function (error, result) { ... })`.

Подробности: `docs/design/05-plugins.md` и `docs/design/04-protocol.md`.
