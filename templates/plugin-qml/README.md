# Шаблон QML-плагина

Плагин с одной панелью на QML и без бэкенда. Окно грузит панель с диска, шаг сборки не нужен.

## Как сделать плагин

1. Скопируй каталог `templates/plugin-qml` под любым именем: имя каталога ни на что не влияет.
2. В `plugin.json` смени `id`. Он задаётся только здесь: QML получает его от окна через свойство `pluginId` корня панели. Допустимы строчные буквы, цифры, `.`, `_` и `-`, начинается с буквы или цифры; `keymap` зарезервирован.
3. Положи каталог плагина внутрь каталога, где `roostd` ищет плагины: `<каталог состояния>/plugins`. Каталог состояния — `$ROOST_CONFIG`, иначе `$XDG_CONFIG_HOME/roost`, иначе `~/.config/roost`. Для проверки без правки состояния задай `ROOST_PLUGINS_PATH` — список абсолютных путей через `:`. Каждый путь — каталог, который содержит каталоги плагинов (в каждом свой `plugin.json`), а не сам каталог плагина.
4. Перезапусти `roostd`, затем окно. Проблемы загрузки видны в полосе проблем внизу окна и в stderr `roostd` (терминал, где он запущен). В полосе — проблемы манифестов из `plugins.list` и проблемы загрузчика панелей окна.
5. Раскладка окна пока фиксирована: список сессий и терминал. Панель нового плагина загружается и проверяется, но в окне не появляется: свободная раскладка будет с M5. Открыть панель можно так, как это делает `tests/roost/plugin_template_test.cpp`: окно со своим `PanelSlot` с `panelType` равным полному id панели `<id плагина>.hello`.
6. Правь `qml/HelloPanel.qml`. С `roost --dev` окно перезагружает плагин при изменении файла; правка `plugin.json` требует перезапуска `roostd`.

Корень панели — `Item`; необязательное свойство `pluginId` получает id плагина. Входы и выходы панели объявляются в `inputs` и `outputs` манифеста и должны быть свойствами корня. API — синглтон `Roost` из `import Roost.Api`.

## Как добавить бэкенд

1. Положи исполняемый файл в `backend/` плагина и выставь право запуска: `chmod +x backend/run`. Язык любой, протокол — JSON-RPC 2.0 по stdio, одно сообщение на строку.
2. В `plugin.json` добавь рядом с `contributes`:
   `"backend": { "command": ["backend/run"] }`
   Путь — внутри каталога плагина; бэкенд запускается в нём.
3. В `contributes` объяви команды:
   `"commands": [{ "id": "<id>.doThing", "title": "Do the thing" }]`
4. Бэкенд отвечает на запрос `commands.run` с параметрами `{command, args}`: в `result` кладёт ответ, неизвестную команду отвергает ошибкой `-32602`. Закрытый stdin значит «завершись». Пока бэкенд не запущен или завершился, не ответив, `commands.run` возвращает ошибку `-32003`, и колбэк в QML получает её.
5. Из QML команду зовёт `Roost.commands.run("<id>.doThing", args, function (error, result) { ... })`.
