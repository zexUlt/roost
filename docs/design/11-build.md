# 11. Сборка, тесты, упаковка

- CMake с пресетами, Qt 6 (в CI одна версия, ставится через aqtinstall), C++23, clang, Zig для libghostty-vt.
- Тесты: Qt Test для демона и моделей; Qt Quick Test для QML с `QT_QPA_PLATFORM=offscreen`; адаптеры — на записанном выводе `claude agents --json` плюс тест на настоящем `claude`, который включается явно.
- `ctest` по пресету идёт по три теста сразу (`execution.jobs` в `base` у пресетов тестов; три — ядра macos-15), пресет `tsan` — по одному. Параллельность безопасна, пока тест берёт только свои временный каталог и сокет (`ROOST_SOCKET`). Тест, которому нужен общий ресурс, получает `RESOURCE_LOCK` с комментарием, чем делится; `RUN_SERIAL` — только замерам времени (`frame_budget_test`).
- CI на GitHub Actions: сборка и тесты на macOS arm64 и Linux x64, гейты format и tidy.
- Упаковка: macOS — `.app` через `macdeployqt` в `.dmg`; Linux — AppImage через `linuxdeploy-plugin-qt`.
- Раскладка `cmake --install` (`cmake/Install.cmake`), одна на ОС; дерево сборки (`build/<preset>/bin`, `build/<preset>/roost-plugins`) не меняется, `roost` в нём не `MACOSX_BUNDLE`, `.app` собирается при установке:
  - macOS: `<prefix>/roost.app`; `Contents/Info.plist` из `packaging/macos/Info.plist.in` (id `io.github.zexult.roost`, версия проекта, `LSMinimumSystemVersion` из `CMAKE_OSX_DEPLOYMENT_TARGET`, без него — из дефолта компилятора); `Contents/MacOS/{roost,roostd,claude-adapter}`; манифесты, QML и `qmldir` плагинов — `Contents/Resources/roost-plugins/<id>/`; библиотека QML-модуля — `Contents/PlugIns/roost/`; в каталогах плагинов на код относительные симлинки (манифест и `qmldir` проверяют путь текстом, симлинк проходит); лицензии — `Contents/Resources/licenses/`.
  - Linux (префикс — `usr/` AppDir): `bin/{roost,roostd}`; `lib/roost/plugins/<id>/` с кодом на месте; `share/applications/roost.desktop`, `share/icons/hicolor/256x256/apps/roost.png` (заглушка), `share/licenses/roost/`.
  - Все `install()` — в компоненте `roost` (`cmake --install ... --component roost`), чтобы компонент SDK (M8) не попал в `.app`.
  - Лицензии: `LICENSE`, `NOTICE`, `THIRD_PARTY_LICENSES`, `licenses/LGPL-3.0.txt`, `licenses/GPL-3.0.txt` (тексты с gnu.org).
  - `INSTALL_RPATH` у каждой цели: `@executable_path/../Frameworks` и `@loader_path/...` на macOS, `$ORIGIN/../lib` и относительные пути от каталога плагина на Linux, плюс каталоги Qt, с которым собрано (`INSTALL_RPATH_USE_LINK_PATH`): на macOS CMake ставит их перед нашими, на Linux после. Опция `ROOST_INSTALL_RPATH_TO_QT` (по умолчанию ON): установленное дерево само находит Qt сборочной машины; упаковка macOS оставляет ON (по этим путям `macdeployqt` находит фреймворки) и после него удаляет из бандла run path не вида `@...`. Шаблоны и тесты не ставятся; собственные `install()` libghostty-vt отключены (`EXCLUDE_FROM_ALL`), она линкуется статически.
  - Проверка: `tests/install/install_layout_test.cpp` ставит в временный префикс, сверяет полный список файлов, симлинки, лицензии, `Info.plist`/`.desktop`, run path и запускает установленный `roostd` без `ROOST_PLUGINS_PATH` и установленное окно `roost --smoke-sessions` против него (модуль QML сессий через симлинк).
- Упаковка macOS (`tools/package_macos.sh`, `tools/check_bundle.sh`): из дерева сборки с пресетом `release`, с Qt, чьи `macdeployqt` и `qmake` первые в `PATH`:

  ```
  cmake --preset release && cmake --build --preset release
  tools/package_macos.sh build/release out      # печатает путь .dmg
  tools/check_bundle.sh out/stage/roost.app out/roost-*.dmg
  ```

  - Скрипт упаковки: `cmake --install` в `out/stage`; платформенный плагин `offscreen` рядом с `cocoa` (`macdeployqt` кладёт один `cocoa`; `offscreen` нужен смоку без дисплея); `macdeployqt` с `-executable=` на каждый Mach-O (`roostd`, `claude-adapter`, библиотека QML-модуля сессий) и `-qmldir=` на `src/roost` и QML каждого плагина (`-qmlimport` для `RoostSessions` не нужен: он лежит в каталоге плагина, а с ним модуль скопировался бы второй раз в `Resources/qml`); удаление run path не из бандла (`@...`); ad-hoc `codesign --force -s -` изнутри наружу: код вне фреймворков, фреймворки, `.app`; `hdiutil create` образа с `roost.app`, ссылкой `/Applications` и `Licenses/` (до трёх попыток с паузой: на раннерах GitHub бывает «Resource busy»; неполный `.dmg` между попытками удаляется). В поставляемом `.app` лежит `libqoffscreen.dylib` намеренно: безголовый смок идёт на том же бандле, что уходит пользователю.
  - Проверка бандла: `otool -L` и run path каждого Mach-O — только `@rpath`/`@executable_path`/`@loader_path` и системные пути, каждая зависимость разрешается как у dyld (`@loader_path` — каталог файла, `@executable_path` — `Contents/MacOS`, `@rpath` — по каждому `LC_RPATH` файла) и должна найтись внутри бандла, иначе FAIL; `QtCore`, `QtQuick/Controls`, `QtQuick/Layouts` в `Contents/Resources/qml`; лицензии; `codesign --verify --deep --strict`; `roost --smoke-sessions` из бандла в изолированном окружении (свой `HOME`, сокет и конфиг, несуществующий `SHELL`, поддельный `claude`): запущенный roostd — из бандла, Qt он грузит только из бандла и `QtCore` оттуда загружен (пустой ответ `lsof` — FAIL); roostd и поддельный attach убираются по pid.
    - Проверка `.dmg` (второй аргумент `tools/check_bundle.sh`): `hdiutil verify`; `hdiutil attach -readonly -nobrowse -noautoopen -mountpoint <tmp>` с `detach` на любом выходе; в образе `roost.app` (`codesign --verify --deep --strict`), ссылка `Applications` -> `/Applications`, `Licenses/` со всеми файлами.
  - Подпись ad hoc, не Developer ID: Gatekeeper спрашивает, снимать карантин нужно `xattr -dr com.apple.quarantine`.
  - CI: `package.yml`, job `macos` (тот же Qt, zig и кеши, что у `test (release)`), артефакт `roost-macos-dmg` (хранится 7 суток, на теге `v*` — 90); на теге `v*` job падает, если тег без `v` не равен `CFBundleShortVersionString` собранного `.app` (версия проекта). Правка упаковки доказывается запуском на своей ветке: `gh workflow run package.yml --ref <ветка>`.
- Пакеты: что получается и откуда запускать.
  - Имена: `roost-<версия>-macos-<arch>.dmg` (`<arch>` — `uname -m` машины сборки; в CI это `arm64`, `.dmg` только для Apple silicon) и `roost-<arch>.AppImage`, `<arch>` — `x86_64` или `aarch64`. Каждый пакет собирается на машине своей архитектуры: кросс-сборки нет.
  - Локально AppImage: на Linux нужны собранное дерево `release` (Qt первым в `PATH`, `qmake` оттуда), `curl` и сеть для инструментов упаковки (скрипт скачивает их по тегу и проверяет sha256):

    ```
    cmake --preset release && cmake --build --preset release
    tools/package_linux.sh build/release out      # печатает путь AppImage
    tools/check_appimage.sh out/roost-$(uname -m).AppImage
    ```

    Локально `.dmg` — команды выше, в описании упаковки macOS. Оба пакета собираются из дерева `release`; тяжёлая сборка — по возможности в CI.
  - Запуск `package.yml`: на теге `v*`, на `workflow_dispatch` и на пуше в trunk по условию `on.push` самого workflow; на pull request он не идёт. Правка упаковки или самого workflow доказывается запуском на своей ветке: `gh workflow run package.yml --ref <ветка>`. Артефакты запуска: `roost-macos-dmg` и `roost-<arch>.AppImage`, хранятся 7 суток, на теге `v*` — 90.
- Упаковка Linux (AppImage; `tools/package_linux.sh <build dir> <out dir>`, на x86_64 и aarch64, на машине своей архитектуры): собранное дерево (`build/release`, Qt в PATH) → `cmake --install` (с `ROOST_INSTALL_RPATH_TO_QT=OFF`) в `AppDir/usr` → `linuxdeploy --plugin qt` копирует Qt и библиотеки (`QML_SOURCES_PATHS` — `src/roost` и `plugins/*/qml`, чтобы попал и `QtCore`, который импортирует только QML плагина; `EXTRA_PLATFORM_PLUGINS=libqoffscreen.so`; `--executable` `roostd` и `claude-adapter`, `--library` модуль QML сессий) → из AppDir убирается то, что roost не использует (стили Qt Quick Controls кроме Fusion и Basic, Dialogs, Effects, Particles, Shapes, VectorImage, LocalStorage, XmlListModel, плагины imageformats и tls, Qt-библиотеки, которых после этого никто не требует) → в `usr/share/licenses/roost/` кладётся `licenses/ICU-LICENSE.txt` (текст лицензии ICU из репозитория: Qt образа линкует ICU отдельными библиотеками; в macOS-бандле ICU нет) → `appimagetool` со статическим рантаймом (в Ubuntu 24.04 нет libfuse2), который берётся из закреплённого релиза `AppImage/type2-runtime` (тег и sha256 на архитектуру) и передаётся через `--runtime-file`: сам `appimagetool` ничего не скачивает. Библиотеки, которые есть на любом десктопе, образ не несёт (`--exclude-library`, список в `packaging/linux/system-libraries.txt`): на чистой машине должны быть GLib/GThread, PCRE2, D-Bus, systemd, libgcrypt, libgpg-error, libcap, XZ, LZ4, Zstandard, bzip2, Brotli, expat, libpng16, Kerberos (libkrb5, libkrb5support, libk5crypto, libgssapi_krb5, libcom_err, libkeyutils), libbsd, libmd, libX11, libX11-xcb, libXau, libXdmcp, libxcb и его libxcb-glx/-randr/-render/-shm/-sync/-xfixes, libxkbcommon, плюс FreeType, fontconfig, libGL/libEGL, libstdc++ (их и так не копирует linuxdeploy). Шаг 10 (чистый `ubuntu:24.04`) ставит именно их. `packaging/linux/AppRun` первым аргументом `--roostd` запускает `usr/bin/roostd`, иначе `usr/bin/roost`; окно стартует демон как `$APPIMAGE --roostd`, и у демона своё монтирование, пока он жив. linuxdeploy, его плагин Qt и appimagetool скачиваются по тегу и sha256 (на архитектуру) и запускаются распакованными: FUSE не нужен. Результат — `<out dir>/roost-<arch>.AppImage`. Сборка на Ubuntu 24.04; на целевой машине нужны glibc ≥ 2.39 и libstdc++ от GCC 14 (образ их не несёт). Платформенные плагины Qt в образе — только xcb и offscreen: под Wayland окно работает через XWayland. Стиль Qt Quick Controls — по умолчанию (Fusion на Linux); в образе только Fusion и Basic, так что `QT_QUICK_CONTROLS_STYLE` с другим стилем не поддерживается. Скрипт на время работы ставит `ROOST_INSTALL_RPATH_TO_QT=OFF` в кеше дерева и по выходу возвращает прежнее значение.
- Проверка AppImage: `tools/check_appimage.sh roost-<arch>.AppImage` распаковывает его и проверяет: `ldd` каждого ELF без `LD_LIBRARY_PATH` не даёт «not found»; каждая запись RPATH/RUNPATH каждого ELF начинается с `$ORIGIN` (путь Qt машины сборки, который `ldd` на ней молча разрешил бы, — ошибка); каждая разделяемая библиотека есть в инвентаре лицензий внутри скрипта (путь → заголовок раздела `THIRD_PARTY_LICENSES`), неизвестная — ошибка; заголовок каждого найденного компонента есть в `THIRD_PARTY_LICENSES` образа; `usr/qml/QtCore/qmldir`, ни одной библиотеки из `packaging/linux/system-libraries.txt` в образе (иначе ошибка), тексты лицензий (в том числе `ICU-LICENSE.txt`, совпадающий с `licenses/ICU-LICENSE.txt`), файлы плагинов на месте. Затем сам AppImage запускается с `--smoke-sessions` (offscreen, временные `HOME`, `ROOST_SOCKET`, `ROOST_CONFIG`, фальшивый `claude`, несуществующий `SHELL`) и должен выйти с 0; `roostd` из `<socket>.lock` должен идти из монтирования AppImage (`.../usr/bin/roostd`, `APPIMAGE` в его окружении). Запущенное убивается по pid. Новая библиотека в образе — новая строка в `classify` скрипта и запись в `THIRD_PARTY_LICENSES` и `10-licenses.md` вместе, по согласованию.
- CPU libghostty-vt: `cmake/ghostty.cmake` закрепляет `-Dcpu` для Zig во всех пресетах (иначе Zig собирает под CPU машины сборки, и пакет падает с SIGILL там, где нет её инструкций): x86_64 — `x86_64_v3` (нижняя граница для пользователей: Intel Haswell, 2013, или AMD Zen и новее), Linux aarch64 — `baseline`, Apple arm64 — `apple_m1`; уже заданный `-Dcpu`/`-Dtarget` в `GHOSTTY_ZIG_BUILD_FLAGS` не трогается. Его SIMD (simdutf, highway) выбирает AVX2 или AVX-512 во время работы. `tools/check_appimage.sh` дизассемблирует (`objdump -d`) ELF roost (`usr/bin`, `usr/lib/roost`) и падает на `%zmm`, `%xmm16`–`%ymm31` и `%k0`–`%k7` вне функций, которые выбираются по CPU во время работы (`simdutf::icelake`, `N_AVX3` highway): так сборка под CPU машины сборки не уедет в пакет. EVEX-инструкции на младших регистрах без маски эта проверка не видит.
- CI: джоб `linux` в `.github/workflows/package.yml` (ubuntu-24.04 и ubuntu-24.04-arm): сборка `release`, `ctest`, упаковка, проверка, артефакт `roost-<arch>.AppImage`. Проверка изменения — запуск `gh workflow run package.yml --ref <ветка>`.
- Smoke пакетов на чистой машине (`tools/package_smoke.sh <roost.dmg | roost-<arch>.AppImage> [--launch-services]`, один скрипт на обе ОС): пакет запускается так, как его запускает пользователь, в изоляции (временные `HOME`, `TMPDIR`, `ROOST_SOCKET`, `ROOST_CONFIG`, открытая сессия в `sessions.json`, несуществующий `SHELL`, поддельный `claude`; на macOS ещё `CFFIXED_USER_HOME` во временный `HOME`, чтобы настройки не попали в настоящий `~/Library/Preferences`). Платформа окон — `ROOST_SMOKE_QPA` (`offscreen` по умолчанию: локальный запуск не открывает окон; `cocoa` на macOS и `xcb` на Linux ставит только `package.yml`). Проверяет по порядку:
  - окно пакета `--smoke-sessions` выходит с 0; для каждого окна (первое, второе, окно `open -n`) Qt берётся только из пакета, а платформенный плагин `libq<платформа>` загружен из пакета: на macOS по `DYLD_PRINT_LIBRARIES`, на Linux по `LD_DEBUG=libs` в файл (`calling init:`; библиотека не из каталога `.mount_*` AppImage — сбой); `QtCore` пакета в списке обязателен, пустой список — сбой;
  - после выхода окна roostd жив и идёт из пакета: на macOS `.app`, скопированный `ditto` из смонтированного образа (`hdiutil attach -readonly -nobrowse -noautoopen -mountpoint`, `detach` сразу после копирования) в каталог вида `/Applications`; на Linux из FUSE-монтирования AppImage (запись `fuse*` в `/proc/mounts`, `APPIMAGE=<файл>` в окружении демона: он запущен как `$APPIMAGE --roostd` и держит монтирование сам). Qt, загруженный демоном (`lsof` на macOS, `/proc/<pid>/maps` на Linux), — только из пакета; поддельный attach жив сразу и ещё раз в конце прогона (через 3 с после второго окна и перезапуска адаптера; для `open -n` — после ожидания 3 с);
  - лицензии в пакете (на macOS `Contents/Resources/licenses`, на Linux `usr/share/licenses/roost`, с `ICU-LICENSE.txt`);
  - `roostd --dump` пакета отвечает (первый кадр `rpc`);
  - `claude-adapter`, убитый по pid при ушедшем окне, перезапускается демоном (на Linux это доказывает, что монтирование пережило окно);
  - второе окно `--smoke-sessions` приходит к тому же pid roostd;
  - с `--launch-services` (macOS): запуск через `open -n -W --env ... --stdout --stderr` в отдельном каталоге; roostd идёт из `.app`, поддельный `claude` подключён, через 3 с roostd жив. Сбой самого `open --env` — FAIL, не пропуск.
  Окно `--smoke-sessions` само ждёт attach открытой сессии и падает, если её не открыть: вышедшее с 0 окно без `attach.pid` — сбой, а не повод запускать ещё одно.
  Локальный запуск с `--launch-services` на Mac разработчика всё равно даёт системе записать Saved Application State и записи LaunchServices в настоящий домашний каталог (`CFFIXED_USER_HOME` покрывает только настройки приложения); чистым раннерам CI это безразлично.
  Любой сбой печатается `FAIL:` и даёт код 1, в том числе сбой при очистке (не отсоединился образ, не ушло FUSE-монтирование AppImage за 10 с); запущенное убивается по pid, все attach поддельного `claude` (он пишет pid в `bin/attach.all`), а не только первый и последний.
- CI smoke: job `smoke-macos` (свежий `macos-15`, из артефакта только `.dmg`, без Qt и сборки; падает, если на образе есть Qt: `/opt/homebrew/opt/qtbase`, `qmake`, формулы `qt*`) и `smoke-linux` на x86_64 (`ubuntu-24.04`) и aarch64 (`ubuntu-24.04-arm`): контейнер `ubuntu:24.04` с `--device /dev/fuse --cap-add SYS_ADMIN --security-opt apparmor:unconfined`, без Qt, из артефакта только AppImage. AppImage запускается через FUSE, не через `--appimage-extract-and-run` (тот удаляет распакованное при выходе окна, демону нечем перезапускать бэкенд). Библиотеки десктопа: `ubuntu-desktop-minimal --no-install-recommends` (стандартный набор; ставится в контейнере без запуска служб, `policy-rc.d`), плюс `fuse3`, `procps` для скрипта, `fonts-dejavu-mono` и `xvfb` с `xauth`. Окна идут на настоящих платформенных плагинах пакета: на macOS `ROOST_SMOKE_QPA=cocoa` (у раннера есть сессия GUI), на Linux `ROOST_SMOKE_QPA=xcb` под `xvfb-run`: так ловится нехватка `libxcb-cursor0` или `libxkbcommon-x11` на десктопе, чего `offscreen` не видит. Если он перестанет ставиться в контейнере, замена — явный список пакетов библиотек из `packaging/linux/system-libraries.txt` плюс FreeType, fontconfig, libGL, libEGL.
- Черновик релиза: job `release` (нужны оба smoke; единственный с `permissions: contents: write`) на теге `v*` и на запуске с `draft_release=true`. Собирает `.dmg`, оба AppImage и `SHA256SUMS`, проверяет, что исходники Qt по ссылке в заметках существуют, и делает `gh release create --draft`: черновик не создаёт git-тег, пока не опубликован. Заметки называют версию Qt и ссылку на его исходники (LGPL), лицензию ICU, порог glibc 2.39, X11/XWayland и снятие карантина `xattr -dr com.apple.quarantine /Applications/roost.app`. Публикация — вручную. Прогон без тега: `gh workflow run package.yml --ref <ветка> -f draft_release=true`; тег черновика `dryrun-<id запуска>`; после проверки `gh release delete dryrun-<id> --yes` (`--cleanup-tag` не нужен: тега нет).
- SDK: `roost/plugin.h` (C), `roost/plugin.hpp` (C++-обёртка, только заголовки), `RoostSdkConfig.cmake` с `roost_add_plugin(...)`: скрытая видимость, экспорт только `roost_plugin_*`, структура каталога плагина. Архив SDK на каждый релиз, подключается через `find_package(RoostSdk)`.
- Пример и шаблоны: `samples/session-stats/` (нативный плагин на C++ и QML), `templates/plugin-qml/` и `templates/plugin-native/`. В основную сборку они не входят и собираются в CI отдельно, как сторонний плагин: только против установленного SDK и Qt. Так проверяется, что SDK и шаги из README шаблона достаточны, а пример не опирается на внутренности roost.
- Проверки ABI в CI: на Linux `abidiff` между библиотекой с публичными типами SDK, собранной из HEAD и из последнего тега `sdk-v*`, (дописывание в конец структуры подавлено); на обеих ОС тест размеров и смещений — `sizeof`, `offsetof`, `alignof` публичных структур против файла в репозитории; плагин-фикстура, собранная против прошлого SDK, грузится текущим roost, а фикстуры с чужим major и слишком новыми SDK или Qt отвергаются. В 0.x `abidiff` только сообщает, остальное блокирует.
