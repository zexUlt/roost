# 13. План реализации

Работа идёт этапами. **После каждого — остановка и ожидание отмашки**; следующий этап не начинается автоматически. Каждый этап — стек небольших самодостаточных коммитов; критерий готовности прогоняется и показывается целиком.

| Этап | Содержание | Критерий готовности |
|---|---|---|
| **M0** | каркас: CMake, пресеты, Qt, libghostty-vt, пустые `roost` и `roostd`, CI с гейтами | три пресета зелёные на macOS; `roost --smoke` выходит с 0 под `offscreen`; гейт нейминга ловит намеренное нарушение в каждом из двух стилей; Qt подключён динамически |
| **M1** | `roostd`: кадры, JSON-RPC, шина, хранилище, загрузчик плагинов | тестовый клиент через сокет вызывает команду бэкенда-фикстуры и получает ответ; упавший бэкенд перезапускается и о падении приходит событие; разбиение потока на любые куски даёт те же кадры |
| **M2** | PTY, тёплый пул, каналы сессий, адаптер Claude | список сессий совпадает с `claude agents --json --all`; терминал демона, накормленный записанным потоком, совпадает с эталонным терминалом на том же потоке; снимок после кодирования и декодирования совпадает с исходным; запросы фейкового TUI получают ровно один ответ |
| **M3** | `TerminalSession`, рендер, `TerminalItem` | через настоящий `roostd` ввод доходит до фейкового TUI и его эхо отрисовано; изменение размера доходит до PTY; GUI-поток тратит ≤ 4 мс на кадр, пока 10 терминалов получают по 1 МБ/с; `tsan` и проверки лока чистые |
| **M4** | окно и встроенные плагины: список сессий, терминал. **Рабочий продукт** | список и терминал управляются с клавиатуры без мыши; гейт ловит плагин, который линкует внутреннюю цель roost; перенесённые тесты cc-fleet зелёные; перезапуск окна сохраняет состояние и тёплые сессии; переход к тёплой сессии — один кадр |
| **M5** | раскладка панелей со связями, keymap, палитра команд, SDK 0.1 | две пары «список + терминал» независимы; раскладка переживает перезапуск; встроенный список сессий заменяется плагином-фикстурой без правок ядра; нативная фикстура, собранная вне дерева через `find_package(RoostSdk)`, загружается, а несовместимые отвергаются с сообщением |
| **M6** | уведомления, PR, keep-awake | перенесённые тесты зелёные на macOS и Linux; уведомление о переходе в `blocked` приходит не позже одного опроса |
| **M7** | упаковка `.dmg` и AppImage, архив SDK | AppImage запускается на чистом `ubuntu-24.04` без установленного Qt; `.app` берёт Qt из бандла; тексты лицензий внутри обоих пакетов; подписанный `.app` грузит нативную фикстуру |

**M4 — уже полноценный продукт**: заменяет cc-fleet в ежедневной работе. M5–M7 расширяют его, а не доделывают.

## M0: каркас

Подготовка: на маке `brew install qt zig` (Qt 6.12.0, Zig 0.17.1). Linux проверяется в CI; локально — в Lima VM, если CI недостаточно.

Шаги:

1. `CMakeLists.txt`, `CMakePresets.json` с пресетами `dev`, `asan-ubsan`, `release` (Ninja, `CMAKE_EXPORT_COMPILE_COMMANDS`). CMake падает на компиляторе, отличном от clang.
2. `cmake/ghostty.cmake`: `FetchContent_Declare(ghostty ... GIT_TAG vt-1.0.1)` (коммит `108cacb`), цель `ghostty-vt-static`. Нет Zig в `PATH` — понятная ошибка конфигурации.
3. `src/core/` — статическая библиотека `roost_core`, пока с одной функцией: версия roost и libghostty-vt.
4. `src/roostd/main.cpp` — `QCoreApplication`, `--version`.
5. `src/roost/main.cpp` — `QGuiApplication` и пустое окно на QML; `--smoke` закрывает окно после первого кадра (`QQuickWindow::frameSwapped`).
6. `src/qml_api/` с `.clang-tidy` из ADR 011.
7. `tests/`: Qt Test — терминал libghostty-vt получает `hello\r\n\x1b[31mred`, formatter отдаёт `hello\nred`; запуск `roost --smoke` под `QT_QPA_PLATFORM=offscreen`.
8. `tests/gates/naming/core/` — метод в camelCase; `tests/gates/naming/qml_api/` — метод в PascalCase и симлинк `.clang-tidy` на `src/qml_api/.clang-tidy` (стиль берётся по каталогу файла, поэтому фикстуре нужен тот же конфиг, а не копия). Гейт запускает `clang-tidy` на обоих файлах с флагами компиляции после `--` и требует ненулевой код на каждом; `WarningsAsErrors` наследуется из корня.
9. `.github/workflows/ci.yml`: сборка на `macos-15` (arm64); Linux добавляется, когда решён вопрос «какой Linux» (§14). Qt одной версией через `install-qt-action`, Zig через `setup-zig`; джобы `test` (три пресета), `format` (`clang-format`, `qmlformat`), `tidy` (`clang-tidy-20`), `gates`. Проверка динамической линковки Qt: `tools/check_qt_dynamic.sh` (`otool -L`, на Linux `ldd`).

CI требует репозиторий на GitHub; до его появления критерий M0 прогоняется локально на маке, а Linux-часть ждёт.

## M1: `roostd`

1. `src/core/frame.{hpp,cpp}` — кодек кадров §4 без ввода-вывода: на вход байты, на выход кадры; предел длины кадра, ошибка на превышение.
2. `src/core/rpc.{hpp,cpp}` — JSON-RPC 2.0: запросы, ответы, уведомления, коды ошибок спецификации; таблица методов.
3. `src/core/bus.{hpp,cpp}` — шина событий с подпиской по префиксу имени (`session.*`).
4. `src/core/store.{hpp,cpp}` — JSON на плагин в `~/.config/roost/<plugin>.json`, запись через `QSaveFile` (временный файл и `rename`); каталог переопределяется `ROOST_CONFIG`, тесты всегда задают его.
5. `src/roostd/server.{hpp,cpp}` — `QLocalServer`, каталог сокета 0700, проверка UID пира (`SO_PEERCRED` / `getpeereid`), рукопожатие `hello`.
6. `src/roostd/plugins.{hpp,cpp}` — поиск каталогов плагинов, разбор и проверка `plugin.json`, реестр вкладов с обнаружением конфликтов, запуск бэкендов через `QProcess` (JSON-RPC построчно по stdio), перезапуск с экспоненциальной задержкой и пределом попыток.
7. `src/core/rpc_client.{hpp,cpp}` — клиент сокета: рукопожатие, запросы с `QFuture`, подписки на уведомления и каналы. Им пользуются окно и тесты; `roostd --dump` читает сокет сам, чтобы печатать кадры как есть.
8. `roostd --dump` — подключается к сокету и печатает кадры читаемо.

Тесты: кодек кадров на всех разбиениях потока; ошибки JSON-RPC по спецификации; хранилище не оставляет полузаписанного файла; загрузчик на плагинах-фикстурах, бэкенд — маленький C++-хелпер из `tests/helpers/`, без Python.

## M2: PTY, тёплый пул, каналы сессий, адаптер Claude

1. `src/core/pty.{hpp,cpp}` — `openpty`, `fork`/`exec`, `TIOCSWINSZ`, чтение через `QSocketNotifier`, сбор завершившихся детей.
2. `src/roostd/warm_pool.{hpp,cpp}` — канал на тёплую сессию: PTY плюс терминал libghostty-vt с continuation tracking; ответы на запросы терминала через колбэк записи в PTY; вытеснение по давности просмотра, N из настроек.
3. `session.open`, `session.resize`, `session.close`, кадры ввода и вывода (§4); снимок и подписка на канал в одном проходе цикла событий (§3).
4. `src/roostd/adapter_bridge.{hpp,cpp}` — `AgentAdapter` поверх JSON-RPC к бэкенду плагина.
5. `plugins/claude/` — бэкенд `claude-adapter` на C++ и QtCore: опрос `claude agents --json --all` раз в 3 с (как `POLL_SEC` в cc-fleet), разбор в `Session`, события `session.stateChanged`; `AttachCommand` — `claude attach <id>`.

Тесты: адаптер на записанных ответах `claude agents --json` в `tests/fixtures/`; терминал демона против эталонного терминала на одном записанном потоке, поток режется на куски в случайных местах; снимок туда и обратно; PTY и пул на фейковом TUI из `tests/helpers/` (рисует адресацией курсора, шлёт DA1 и CPR); тест на настоящем `claude` только при `ROOST_REAL_CLAUDE=1`, без ввода в сессии. Замер RSS тёплого attach записывается в prior-art.

## M3: `TerminalSession` и `TerminalItem`

1. `src/terminal/terminal_session.{hpp,cpp}` — терминал, render state, мьютекс; все вызовы libghostty-vt через методы с проверкой лока (§3).
2. `src/terminal/io_thread.{hpp,cpp}` — один поток на окно: `rpc_client` из M1, разбор кадров, запись в терминалы сессий.
3. `src/terminal/renderer.{hpp,cpp}` — `begin_update` под локом, `end_update`, перестройка грязных строк. Строки рисуются через `QSGTextNode` (Qt 6.7+, `QQuickWindow::createTextNode()`): шейпинг и замена шрифтов из коробки. Если бюджет кадра не сходится — атлас глифов; решение по замеру, оба варианта на одном бенчмарке.
4. `src/qml_api/terminal_item.{hpp,cpp}` — `QQuickItem`, показывает одну `TerminalSession`, `updatePaintNode` отдаёт рендереру.
5. Ввод: энкодеры клавиш и мыши, вставка с bracketed paste, выделение и копирование, прокрутка scrollback; `session.resize` (§3).
6. Режим разработки `roost --session <id>`: одна сессия на всё окно, без плагинов.
7. Пресет `tsan`. Замер памяти терминала libghostty-vt в окне при пустом и полном scrollback — в prior-art.

Тесты: таблица кодирования клавиш; содержимое ячеек после известного VT-потока (не скриншоты: шрифты в CI разные); сквозной тест окно → `roostd` → фейковый TUI: эхо ввода и размер PTY; бенчмарк кадра с `QSG_RENDER_LOOP=threaded` (§9). TUI Claude проверяется руками и в критерий не входит.

## M4: окно, список сессий и терминал

1. `src/api/`: сервисы сессий, команд, хранилища и шины и диспетчер методов по именам из §4; вызовы только из GUI-потока, с проверкой в отладке (§5).
2. `src/qml_api/`: синглтоны `Roost.sessions` (`QAbstractListModel`), `Roost.commands`, `Roost.store`, `Roost.bus` — адаптеры над `src/api/` без своей логики.
3. Загрузка QML плагинов через `QQmlComponent`, перезагрузка при изменении файла в режиме разработки. Список плагинов окно берёт у `roostd` методом `plugins.list` (§4).
4. Гейт: цели в `plugins/` не линкуют `roost_core`, `roost_qml_api` и другие внутренние цели; проверяется на фикстуре-нарушителе.
5. Оболочка: фиксированная раскладка «список | терминал» (свободная — M5).
6. `plugins/sessions/` — QML-модуль плагина с моделью на C++ (§5, «Нативные плагины»): собирается в дереве, линкует только Qt, данные берёт из `Roost.sessions`; категории, пины, архив, имена, цвета, свёртка, непрочитанные, поиск; клавиши, взятые у cc-fleet (↑/↓ и j/k, Enter, n, /, c, e, d, x, v, r/R, a, </>).
7. `plugins/terminal/` — панель над `TerminalItem`.
8. Тёплые терминалы в окне и снимок при подключении (§3).

Тесты: случаи из `test_pins`, `test_tree`, `test_fold_cursor`, `test_subagents`, `test_launched`, `test_title` переносятся в Qt Test и Qt Quick Test как спецификация логики списка.

## M5–M7

- M5: дерево раскладки в JSON, сплиты и вкладки, связи из контекстного меню (§6); keymap: вклады с ключами `mac` и `when`, файл `keymap.json`, сопоставление букв по скан-коду, `keymap.get` и `keymap.changed`, показ конфликтов и переопределений (§16); тесты — таблица разбора клавиш (порядок модификаторов, ⌘ против Control, `mac`, `Cmd` на Linux), разрешение по паре (клавиша, `when`) и `null`, буквы на русской раскладке и Dvorak, клавиша без модификатора не срабатывает в терминале, сохранение через `rename` подхватывается, битый файл оставляет прежнюю таблицу, каталог — временный через `ROOST_CONFIG`; палитра команд. Проверка API: плагин-фикстура заменяет `plugins/sessions/`. SDK 0.1: `plugin.h`, тест размеров и смещений структур, C++-обёртка и `RoostSdkConfig.cmake`, `src/sdk_host/` с рукопожатием и отказами, ключ `native` в манифесте, `abidiff` в CI и тег `sdk-v0.1.0`; замер вызовов через `host->call` и выбор кодировки данных (§5).
- M6: перенос `notify.py`, `pulls.py`, `awake.py` и их тестов; на Linux `notify-send` и `systemd-inhibit`.
- M7: `macdeployqt` и `.dmg`, `linuxdeploy-plugin-qt` и AppImage, тексты LGPLv3/GPLv3 и `THIRD_PARTY_LICENSES` в пакетах; архив SDK; подписанный `.app` с `disable-library-validation` грузит нативную фикстуру, в том числе с атрибутом `com.apple.quarantine` (§12).

После M7: адаптеры Codex и OpenCode, удалённый `roostd` через ssh, редактор связей.
