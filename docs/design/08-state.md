# 8. Состояние и миграция

- `roostd` хранит состояние в JSON под `~/.config/roost/`, отдельное пространство имён на плагин. Запись атомарная: временный файл и `rename`.
- Каталог: `ROOST_CONFIG`, иначе `$XDG_CONFIG_HOME/roost`, иначе `~/.config/roost`. Без `HOME` и без двух переменных выше демон не стартует, а не пишет в корень. Созданный демоном каталог закрыт правами 0700. Файл плагина — `<id>.json` с правами 0600. В id только строчные латинские буквы, цифры, `.`, `_` и `-`, первым символом буква или цифра: на нечувствительной к регистру ФС macOS `Claude` и `claude` иначе стали бы одним файлом. Файл, который не разбирается, — ошибка, а не пустой документ. Подкаталог `agent-icons/` — не состояние, а значки агентов пользователя (`<agent>.svg` или `.png`, `default.svg` — для остальных агентов): его читает панель сессий при создании, демон не трогает; нет пригодного каталога конфига (`HOME` не абсолютный) — только встроенные значки.
- `keymap.json` в том же каталоге — файл хоткеев пользователя (§16). Демон его читает, а пишет только по `keymap.setCommand` и `keymap.resetCommand` из окна (§16, «Запись из окна»); неразборный `keymap.json` — исключение из правила выше: действует прежняя таблица клавиш. Id плагина `keymap` зарезервирован, чтобы файл состояния плагина с ним не совпал.
- `agent-icons/` в том же каталоге — иконки агентов пользователя (читает панель списка сессий при создании, `plugins/sessions/model/agent_icon.hpp`): `<агент>.svg`, затем `.png`; потом встроенная иконка агента; потом `default.svg`, `default.png` пользователя; иначе встроенная `default.svg`. Имя агента вне `[A-Za-z0-9._-]+` (и `.`, `..`) получает только две последние ступени. Файл, который не загрузился, заменяется встроенной иконкой. Каталог берётся по тому же правилу, что и каталог состояния; нет каталога — только встроенные иконки.
- Документы окна `layout.json` (раскладка панелей), `settings.json` (общий раздел настроек) и `updates.json` (отклонённая версия обновления, §17) лежат в том же каталоге и принадлежат хранилищу, а не плагину: `store.get`, `store.set` и `store.patch` (§4) принимают их id без плагина. Все три id зарезервированы, плагин с таким id не загружается (причина в проблемах). Документ `layout` окно читает один раз при старте и пишет патчем (`store.patch`), но патч — весь документ окна (`{version, root, listsHidden}`; ключи узла, которых у нового узла нет, обнуляются, и `listsHidden` обнуляется, когда списки показаны): после перетаскивания разделителя, шага ширины или правки раскладки (разделить, в стопку, закрыть, связь; 06-panels.md) окно записывает всю свою раскладку, а не только `sizes`, одним патчем на правку. Правка `layout.json` другим процессом между стартом окна и его следующей записью затирается. Пока документа нет, окно показывает раскладку по умолчанию (06-panels.md) и в `layout` ничего не пишет до первого изменения размера. Состояние «списки скрыты» — необязательное поле верхнего уровня `listsHidden: true` (`version` остаётся 1: поле необязательное, и версия по правилу выше не растёт), одно на окно; смысл — в 06-panels.md, «Скрыть и показать списки». Roost без этого поля игнорирует его при чтении и не стирает при записи (его патч не называет ключ), поэтому скрытые списки переживают запись старой версии. Второе окно на том же каталоге не поддерживается: правки `layout` из другого процесса применяются при следующем старте окна. Значения настроек плагина лежат в его собственном документе под ключом `settings`, поэтому `Roost.store` плагина работает как раньше. Несколько писателей одного документа пишут патчем, а не целым документом: `store.patch` вливает патч в текущий документ (RFC 7386), так что правки разных ключей не затирают друг друга. `keymap` по-прежнему закрыт для `store.*`. Ключи документа `settings`: `theme` — id темы, `terminalFont` — `{family, size}` шрифта терминала, `uiFontSize` — размер шрифта окна в пунктах (границы и правило отказа — 05-plugins.md), `updates.check` — булево, по умолчанию `true`: `false` выключает проверку нового релиза (§17), `plugins.disabled` — `{"plugins": {"disabled": [id, ...]}}`, id плагинов, которые `roostd` не загружает (05-plugins.md); `roostd` читает ключ один раз при старте, правка действует после его перезапуска. Окно настроек (05-plugins.md) пишет общий раздел только патчем и по одному ключу на правку, страница плагина — свой документ под ключом `settings`; `keymap.json` окно не пишет. Ключ `theme` — id темы (05-plugins.md): окно и `roostd` следят за документом и перечитывают его после каждой записи; ручная правка `settings.json` на диске без `store.set` или `store.patch` ими не замечается.
- Состояние прежнего TUI roost не импортирует: пользователь один, и категории с именами он переносит руками один раз. Совместимость форматов не держится.
- Из прежнего TUI переезжает логика: категории, пины, архив, имена, цвета, непрочитанные, переходы и тексты уведомлений, поиск PR по worktree, keep-awake. Его тесты (`test_app`, `test_listview`, `test_pins`, `test_tree`, `test_fold_cursor`, `test_notify`, `test_pulls`, `test_awake`, `test_subagents`, `test_launched`, `test_title`) переносятся в Qt Test случай за случаем.

## Документ `sessions`

Плагин `sessions` хранит список в документе `sessions` (`<ROOST_CONFIG>/sessions.json`), версия 1. Ключ сессии — `<agent>/<id>`: id плагина не содержит `/`, первая косая черта делит ключ однозначно.

```json
{
  "version": 1,
  "categories": { "claude/bg-0a1b": "work" },
  "names": { "claude/bg-0a1b": "имя" },
  "archived": ["claude/bg-1b2c"],
  "colors": { "work": 0 },
  "pinned": ["work", ""],
  "folded": [""],
  "unread": ["claude/bg-2c3d"],
  "states": { "claude/bg-0a1b": "working" },
  "view": {
    "list": { "query": "", "tab": "all", "archive": false, "compact": false, "opened": "claude/bg-0a1b" }
  }
}
```

- `view` — вид списка по экземплярам панели: ключ — id панели в раскладке (`list` в раскладке по умолчанию, `docs/design/06-panels.md`), значение — `query`, `tab`, `archive`, `compact`, `opened` и необязательный `newAgent` (агент, выбранный в форме новой сессии последним; ключа нет, пока выбора не было, `06-panels.md`). Два списка в окне пишут разные ключи. Документ прежнего вида хранил эти пять ключей прямо в `view`; экземпляр без своего ключа читает их как начальные значения и не стирает: они остаются в документе. Панель без id экземпляра (список вне раскладки) работает с таким общим `view`.
- Список пишет в документ патчем (`store.patch`), а не целиком: патч — разница между последним известным документом хранилища и состоянием списка. Чужой документ принимается по ключам, неотправленные правки списка остаются (`06-panels.md`). Ключи документа, которых список не знает, он не трогает.
- Категория `""` — «Uncategorized». `colors` — индекс палитры 0–7: категории получают цвета по очереди, после восьмой повторяется наименее используемый; у `""` цвета нет. `pinned` хранит порядок закрепления.
- `version` нет или целое число 1 — документ читается и пишется. Любое другое значение (2, 2.5, `1e30`, `-5`, строка) — список показывается, но не пишется: старый roost не затирает новый документ. В таком состоянии правки меняют только память, сохранять нечего.
- Разбор прощает по записи: запись неверного типа или с ключом не вида `agent/id` отбрасывается, остальные читаются. Раздел неверного типа считается пустым. Повторный пин остаётся на последней позиции. Правка с ключом не вида `agent/id` отклоняется.
- Записи не чистятся сами: исчезновение сессии из `sessions.list` может быть временным. Запись убирает только `Forget(key)` после удаления сессии.
- Непрочитанное считается по смене состояния: сессия непрочитана, если её состояние изменилось на любое, кроме `working`, или она появилась в таком состоянии, и она не открыта. Открытая сессия не бывает непрочитанной, открытие её прочитывает. `states` хранит последние виденные состояния, поэтому сессия, закончившая работу без окна, при загрузке непрочитана. Документ без `states` или с `states` из одних битых записей — первый запуск: первый список только запоминается, непрочитанного нет. `Forget(key)` убирает и сессию из последнего списка: если `roostd` её ещё перечисляет, следующий `Update` считает её новой.
- Порядок строк строит закреплённое множество непрочитанных: оно обновляется только когда сессия становится непрочитанной, не будучи ею раньше (в том числе уже закреплённая, прочитанная и снова непрочитанная), и в документ не пишется. `Restore` его не сбрасывает. `Restore` всегда берёт состояние из документа; свои неотправленные правки список кладёт в документ до `Restore`.
