# 12. Доверие

- Плагины без песочницы. Плагин видит всё, что отдаёт API, включая транскрипты, и может печатать в сессии. Ставить только доверенные.
- Нативный плагин работает в процессе окна с его правами и памятью. Чтобы `.app` с hardened runtime грузил библиотеки, подписанные другим Team ID, нужен entitlement `com.apple.security.cs.disable-library-validation`: тогда окно грузит библиотеку с любой подписью, но неподписанную на arm64 не грузит и атрибут `com.apple.quarantine` не снимает. Не проверено, проверяется в M9.
- Сокет `roostd` — только для своего пользователя: каталог 0700, на Linux проверка `SO_PEERCRED`, на macOS — `getpeereid`.
- Хуки агентов и любые правки чужих конфигов — только по явному согласию в UI.
- Команды плагина `notifications` (`settings.commands`, 05-plugins.md) запускаются `bash -c` с правами пользователя: это его собственный текст из его настроек, не граница безопасности. Документ `notifications` пишет тот, кто может писать в документы: страница настроек (QML плагина), любой клиент сокета `roostd` (`store.set`, `store.patch`; сокет только для своего пользователя) и сам бэкенд (только `results`). Поэтому право писать в сокет равно праву исполнять код пользователя, как у любого плагина (первый пункт). Данные сессии — название, сообщение, рабочий каталог — приходят от агента или из удалённого содержимого и недоверенные: название сессии может быть любым текстом, в том числе `$(...)` и кавычками. Они передаются команде только окружением (`ROOST_*`) и stdin (JSON) и никогда не подставляются в текст `run`: подстановка превратила бы название в исполняемый код. Раскрывать их внутри команды нужно в кавычках (`"$ROOST_MESSAGE"`), как любые недоверенные данные. Контракт и пример — 05-plugins.md.
