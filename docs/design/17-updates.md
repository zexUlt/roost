# 17. Обновления

Окно узнаёт, что вышел релиз новее его самого, и говорит об этом одной строкой. Где окно умеет ставить (сейчас macOS, раздел «Установка и перезапуск»), в строке есть кнопка «Install and restart»: скачать пакет, проверить, поставить, запустить новую версию и закрыть это окно, только по клику. Где не умеет (Linux до #251, запуск не из установленной копии), в строке только ссылка на страницу релиза, и релиз ставит пользователь сам. Пакет окно умеет скачать и проверить (раздел «Скачивание и проверка»).

Релиз несёт `SHA256SUMS.minisig`: подпись minisign файла `SHA256SUMS`, доверенный комментарий `roost <тег> SHA256SUMS`, открытый ключ — `packaging/minisign.pub` (устройство и ротация ключа — 11-build.md). Проверка подписи в приложении — #249; в окне её пока нет.

## Проверка

`roost::Updates` (`src/qml_api/updates.hpp`, `Roost.updates`) живёт в окне, не в `roostd`. Первая проверка идёт, когда окно подключилось и прочитало документ `settings`; дальше таймер каждые 24 часа. Запрос — `GET https://api.github.com/repos/zexUlt/roost/releases/latest` через `QNetworkAccessManager` (`Accept: application/vnd.github+json`, `User-Agent: roost/<версия>`), таймаут передачи 30 с, повторов нет: следующая попытка — по таймеру. Второе окно проверяет само.

- `html_url` предлагается, только если начинается с `https://github.com/zexUlt/roost/releases/`: ссылку открывает система, а ответ пришёл из сети. Иная ссылка (`file:`, чужой хост) — сбой с причиной `the answer has a release page outside the repository`, ничего не показывается.
- Из ответа берутся `tag_name` (`vX.Y.Z`), `html_url` и `assets[]` (`name`, `browser_download_url`: для скачивания). Версии сравниваются числами по частям (`0.10.0` новее `0.9.0`), а не текстом; версия окна — начало `VersionString()` (`src/core/version.hpp`). Тег не вида `vX.Y.Z` (суффикс, две части, нет `v`) не предлагается и не ошибка. Предлагается только версия новее версии окна; `draft: true` и `prerelease: true` не предлагаются.
- Сбой (ошибка сети, HTTP не 200, ответ не объект JSON, нет строк `tag_name` и `html_url`) ничего не показывает и пишется в лог одной строкой `qWarning` на причину: пока та же причина повторяется, строка не повторяется; хороший ответ сбрасывает счёт. Причина — `HTTP <код>`, `network error: <текст Qt>`, `the answer is not a JSON object`, `the answer has no tag_name and html_url`, `the answer has a release page outside the repository`.
- HTTPS идёт через TLS-бэкенд Qt: в AppImage `usr/plugins/tls/libqopensslbackend.so` (libssl3 он берёт из системы во время работы), в `.app` `Contents/PlugIns/tls/libqsecuretransportbackend.dylib` (TLS системы). Оба файла проверяют `tools/check_appimage.sh` и `tools/check_bundle.sh` (11-build.md). Без бэкенда проверка — сбой `network error`.
- Адрес запроса для тестов подменяет переменная окружения `ROOST_TEST_UPDATES_URL`; в работе её не задают. Пустая, но заданная — запросов нет вообще: так её ставят бинарники тестов (`tests/helpers/test_environment.cpp`), чтобы ни один тест не ходил в GitHub. Только для тестов и две другие переменные, которые читаются, лишь пока `ROOST_TEST_UPDATES_URL` задана и не пуста: `ROOST_TEST_UPDATES_PUBLIC_KEY` — текст `minisign.pub`, которым проверяется подпись вместо встроенного ключа (тестовые файлы подписаны ключом тестов, не релизным), и адрес файлов релиза, который берётся от адреса проверки (`<схема и хост из ROOST_TEST_UPDATES_URL>/releases/download/<тег>/`). `ROOST_CACHE` — каталог кеша вместо кеша пользователя, как `ROOST_CONFIG` для состояния; тесты скачивания задают его своим временным каталогом.

## Скачивание и проверка

`Roost.updates.download()` скачивает и проверяет пакет релиза, который предложила проверка; код — `UpdateDownload` (`src/qml_api/update_download.{hpp,cpp}`, принадлежит `Updates`), сама проверка — чистые функции без сети в `src/core/update_verify.{hpp,cpp}`. Кнопку «Install and restart» нажимает пользователь, и она вызывает `install()`, а тот `download()` (раздел «Установка и перезапуск»); свойства и сигнал `packageReady` нужны установщикам (#250, #251).

Что качается: пакет этой платформы и этой архитектуры плюс `SHA256SUMS` и `SHA256SUMS.minisig` того же релиза. Имя пакета — `packageAssetName`: macOS — `roost-<версия>-macos-<arch>.dmg` (`arch` — `QSysInfo::buildCpuArchitecture()`, то есть `uname -m` сборки: `arm64` или `x86_64`, как в `tools/package_macos.sh`), Linux — `roost-x86_64.AppImage` или `roost-aarch64.AppImage`. На другой системе (или Linux другой архитектуры) `canDownload` — `false`, `download()` ничего не делает.

- Адрес каждого из трёх файлов — `browser_download_url` из ответа проверки и должен начинаться с `https://github.com/zexUlt/roost/releases/download/<тег>/`, дальше одно имя файла: без `/`, `\`, `?`, `#` и `%` (путь вверх, запрос, экранирование не проходят). Иной адрес, как и релиз без одного из файлов, — сбой до первого запроса (`the release has <имя> at an address outside the repository`, `the release has no file <имя>`). Переходы на хранилище GitHub (`objects.githubusercontent.com`) выполняет Qt по своей безопасной политике (`NoLessSafeRedirectPolicy`: с HTTPS на HTTP не идёт).
- Файлы пишутся потоком, пакет целиком в памяти не держится. Пределы: `SHA256SUMS` 1 МиБ, подпись 16 КиБ, пакет 1 ГиБ (по `Content-Length` и по принятым байтам); таймаут передачи 30 с (отсутствие данных), повторов нет.
- Каталог попытки — `download-XXXXXX` в `<кеш>/updates/` (`ROOST_CACHE`, иначе `QStandardPaths::CacheLocation`: `~/Library/Caches/roost` на macOS, `~/.cache/roost` на Linux). Одна попытка — один новый каталог. Каталог попытки, оставшийся от аварийного выхода и старше суток, чистится при следующем старте. Скачивание одно: `download()` при идущем или готовом — ничего (готовый пакет не качается заново); при упавшем — новая попытка.
- Порядок: `SHA256SUMS`, подпись, затем проверка подписи и поиск строки пакета, и только потом пакет: пакет не качается, если подпись или строка не прошли. После пакета — SHA-256 файла (`QCryptographicHash`, потоком) против строки.
- Подпись — minisign, ключ в приложении — `packaging/minisign.pub` (CMake читает файл и вкомпилирует строку ключа, `src/qml_api/CMakeLists.txt`; тот же файл у релизного workflow, #248). Проверяет Monocypher (`third_party/monocypher`, 10-licenses.md): Ed25519 с SHA-512 (`monocypher-ed25519`). Формат `ED` — Ed25519 над BLAKE2b-512 файла (по умолчанию у minisign), `Ed` — над самим файлом (старый); оба принимаются. Порядок проверки: идентификатор ключа в подписи совпадает с ключом; подпись `SHA256SUMS`; подпись доверенного комментария (над подписью и текстом комментария); комментарий ровно `roost <тег> SHA256SUMS`, чужого релиза файлы не проходят. Строка пакета в `SHA256SUMS` (`<64 hex>  <имя>` или `<64 hex> *<имя>`, имя целиком) должна быть одна: нет строки, две строки или строка, которая не строка контрольной суммы, — сбой.
- Любой сбой или несовпадение: каталог попытки удаляется, ничего не остаётся, причина — одной строкой в `downloadError` и в журнале (`roost: the download of the update failed: <причина>`).

Интерфейс (`Roost.updates`): `canDownload` — есть предложение и пакет для этой платформы; `downloadState` — `""` (ничего), `"downloading"`, `"ready"`, `"failed"`; `downloadProgress` — доля пакета, 0..1 (пока размер неизвестен, 0); `downloadError` — причина сбоя. Только C++: `downloadedPackage()` — путь проверенного пакета в состоянии `ready` (иначе пустая строка) и сигнал `packageReady(QString path)`. Каталог живёт, пока живо окно, до следующего скачивания и до отмены: установщик использует пакет, не дожидаясь выхода окна.

Отмена: новое предложение (вышла версия новее или та же перестала предлагаться) и `updates.check: false` отменяют идущее скачивание (и сбрасывают готовое) и удаляют каталог; тот же релиз при повторной проверке скачивание не трогает.

## Установка и перезапуск

Общая часть (`Updates::install()`, `src/qml_api/updates.{hpp,cpp}`) не зависит от платформы; платформенный установщик — три функции в `src/qml_api/update_install.hpp`, одна реализация на платформу, выбор при компиляции (как `packageAssetName`): `installTarget()` — что можно заменить на месте, `installPackage(запрос)` — заменить, `relaunch(цель)` — запустить заменённое. macOS — `update_install_macos.cpp`, остальные системы — `update_install_unsupported.cpp` (`installTarget()` пуст). Куда подключается #251: третий файл `update_install_linux.cpp` с теми же тремя функциями (`installTarget()` — `$APPIMAGE` по тому же правилу, что у `DaemonLauncher::CommandFor`, пусто вне AppImage; `installPackage` — скачать рядом, `chmod +x`, переименовать поверх), строка в `src/qml_api/CMakeLists.txt` и ветка `if(...)` там же; кнопка, состояния, скачивание и сверка дайджеста общие и не меняются.

`Roost.updates`: `canInstall` — есть предложение, есть пакет для платформы и `installTarget()` не пуст; `installState` — `""`, `"installing"` или `"failed"`, `installError` — причина сбоя скачивания или установки, `installBusy` — клик в работе (скачивание или установка), `installVersion` — версия, которую этот клик ставит (пусто, пока клика в работе нет). Только C++: сигнал `installed(старый)` (путь старой копии, для журнала и тестов) и швы для тестов `setInstallTarget`, `setRelaunch`, `setQuit`. Строка (`Main.qml`): кнопка «Install and restart» видна при `canInstall`, на время работы она и Dismiss выключены, текст — `Downloading roost v<версия>: N%`, `Installing roost v<версия>...` (версия — `installVersion`, а не `available`: предложение за время установки могло смениться) или причина сбоя (`installError`). Пока клик в работе, строка видна и при выключенной проверке (`updates.check: false`) и при ушедшем предложении, с ходом и выключенными кнопками; ссылка «Release page» есть, пока есть адрес страницы. Когда установка кончилась (сбоем: удачная завершает окно), настройка снова действует: строка уходит, если по ней предложения нет. Клик без предложения, при `canInstall == false` и при идущей установке — ничего. Новое предложение или выключенная проверка во время скачивания отменяют его и сбрасывают сбой установки; во время самой установки пакет из-под неё не удаляется, а закрытие окна ждёт её конца. Если к концу установки (сбой установки или запуска) предложение сменилось или проверка выключена, пакет — от старого предложения, и он сбрасывается: следующий клик качает пакет нового.

Один клик: нет пакета — `download()` и ожидание `packageReady` (сбой скачивания — сбой установки с той же причиной); есть — сразу установка. Установка идёт в рабочем потоке (`QThreadPool`): копия и переименования занимают секунды. Сбой скачивания, который наступает сразу (в релизе нет `.dmg`, адрес вне репозитория, плохой ключ, кеш не пишется), `UpdateDownload` второй раз тем же текстом не объявляет сигналом, поэтому `install()` читает состояние скачивания сразу после `download()`, а не ждёт сигнала: каждый клик кончается видимым состоянием. Сбой установки не удаляет скачанный пакет, пока предложение то же: повторный клик ставит его, не качая заново.

macOS (`installPackage`, порядок и есть инварианты):

1. Цель — запущенный `roost.app` (`installTarget()`: каталог исполняемого файла вида `<имя>.app/Contents/MacOS`; сборка из дерева и всё, что не в `.app`, цели не имеет; не имеет её и бандл, запущенный из App Translocation (путь содержит `/AppTranslocation/`) или с тома, смонтированного только на чтение (`statfs`, `MNT_RDONLY`, например из смонтированного `.dmg`): подмена там ничего у пользователя не заменила бы. Тогда `canInstall` ложно, и в строке только «Release page». Решение — чистая функция `installTargetOf(каталог, только_чтение)`). Каталог цели без права записи — сбой до всего прочего, текстом с путём и ручными шагами (`... is not writable by you. Nothing was changed. To update by hand: download the .dmg from the release page, open it and drag roost.app into <каталог>, replacing the old one.`).
2. SHA-256 пакета сверяется со своей строкой подписанного `SHA256SUMS` ещё раз (`VerifyFileDigest`): файл лежал в кеше, и подмена между проверкой скачивания и установкой не проходит.
3. `hdiutil attach -nobrowse -readonly -noautoopen -mountpoint <каталог рядом с пакетом, mount-XXXXXX> <пакет>`; `roost.app` в образе должен быть каталогом, не ссылкой.
4. `ditto <образ>/roost.app <каталог цели>/roost-new-<id>.app`: рядом с запущенным бандлом, на том же томе, чтобы переименование было атомарным.
5. `hdiutil detach` (при отказе `-force`) сразу после копирования и на любом выходе из функции; каталог точки монтирования удаляется `rmdir`, не рекурсивно. Не отключившийся образ — предупреждение в журнале, а не сбой установки.
6. Проверка копии до подмены: есть `Contents/Info.plist`, исполняемые `Contents/MacOS/roost` и `roostd`, `CFBundleShortVersionString` (`PlistBuddy`, как в `tools/package_macos.sh`) равен предложенной версии. Затем `codesign --verify --deep --strict <копия>` (релиз подписан ad hoc, `tools/package_macos.sh` проверяет его так же): копия без действующей подписи или с файлом, изменённым после подписи, не встанет. Сбой называет путь копии, копия удаляется, старый бандл остаётся.
7. Подмена переименованиями: запущенный бандл → `roost-old-<id>.app`, копия → его место; если вторая не удалась, первая откатывается, сбой называет пути (а если не откатилась — где лежит старая копия и что с ней сделать руками). Старая копия уходит в корзину API системы (`QFile::moveToTrash`), не удаляется; не ушла — остаётся рядом с предупреждением, установка при этом удалась. Корзина отказала — `roost-old-<id>.app` лежит рядом с новой копией, в журнал идёт предупреждение. Тесты подменяют корзину каталогом во временной папке (`InstallRequest::Trash`, `Updates::setTrash`) и корзину пользователя не трогают.
8. Любой сбой до подмены оставляет старый бандл как был, копия `roost-new-<id>.app` удаляется, а сообщение называет пути и причину инструмента (`hdiutil`, `ditto`).

Запуск (`relaunch`): `open -n <бандл>`. LaunchServices запускает новый экземпляр по тому же пути, пока старое окно ещё живо, с окружением запуска из Finder (под него и рассчитан `LoginEnvironment`); так же запускает окно `tools/package_smoke.sh`. Запуск напрямую `QProcess::startDetached` унаследовал бы окружение старого окна и не прошёл бы через LaunchServices. Код выхода `open` не ноль — сбой («roost <версия> is installed, but this window cannot start it: <причина>»): окно остаётся, пользователь запускает новую копию сам. Удачный запуск — `QCoreApplication::quit()`: цикл завершается, `main()` возвращает управление, объекты окна, а с ними каталог скачивания, удаляются. Старый `roostd` продолжает работать, новое окно встречает его через сценарий расхождения версий (04-protocol.md): что сессии продолжают жить, а тёплые прикрепления теряются, описано там.

Карантин: файл, который приложение скачало само через `QNetworkAccessManager`, не получает `com.apple.quarantine`, поэтому шага `xattr` нет. Проверено: `xattr -l` на пакете, скачанном окном с тестового сервера (тест `TheClickInstallsAndRestarts` проверяет это), и на файле, скачанном настоящим `QNetworkAccessManager` с `https://github.com/zexUlt/roost/releases/download/v0.3.1/SHA256SUMS`. У скачанного файла есть только `com.apple.provenance` (его macOS 13+ ставит файлам, созданным приложением; карантина и проверки Gatekeeper он не вызывает). Образ, пришедший браузером, получил бы карантин, и `ditto` (по умолчанию `--qtn`) перенёс бы его на копию.

## Настройка

`settings.updates.check` (05-plugins.md, общий раздел настроек): булево, по умолчанию `true`. `false` отменяет идущий запрос и снимает таймер; запросов нет, пока ключ `false`. Правка `settings` действует в окне сразу (`store.changed`): `true` запускает проверку сразу. Документ `settings`, который не прочитался при подключении, — как пустой: проверка включена, как по умолчанию (тема остаётся как есть). Не булево значение ключа и не объект в `updates` — значение по умолчанию (проверка включена), строка в журнал и строка в полосе проблем: `settings.updates.check must be true or false; the check is on`, `settings.updates must be an object with check; the check is on` (как проблемы шрифтов, `Roost.updates.problems`).

## Строка в окне

`Roost.updates` (только чтение): `available` — версия без `v` или пустая строка, `url` — страница релиза, `enabled` — проверка включена, `problems` — проблемы настройки; один сигнал `changed`. `Main.qml` показывает строку `updateStrip` между раскладкой и полосой проблем: `roost v<версия> is out`, кнопка «Release page» (`Qt.openUrlExternally(url)`) и «Dismiss». Это предложение, а не проблема: цвета — токены `controlBackground` и `windowText`, в `shownProblems` её нет. Строка одна на версию. Кнопка «Install and restart» и тексты состояний — в разделе «Установка и перезапуск».

Dismiss прячет предложение, пока не выйдет версия новее отклонённой. Отклонённая версия лежит в документе окна `updates` (`updates.json`, 08-state.md): `{"dismissed": "X.Y.Z"}`, пишется одним `store.patch`. Пока документ не прочитан, строки нет: отклонённая версия не мелькает при старте. Окна следят за документом (`store.changed`), поэтому отказ в одном окне прячет строку и в другом. Не прочитался документ — как пустой.

## Окно настроек
