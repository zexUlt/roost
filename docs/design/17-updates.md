# 17. Обновления

Окно узнаёт, что вышел релиз новее его самого, и говорит об этом одной строкой. Установки пока нет: ставит релиз пользователь сам, по ссылке на страницу релиза (шаги — #250 и #251 в плане #252). Пакет окно умеет скачать и проверить (раздел «Скачивание и проверка»), но кнопки для этого ещё нет: она придёт с установщиками.

Релиз несёт `SHA256SUMS.minisig`: подпись minisign файла `SHA256SUMS`, доверенный комментарий `roost <тег> SHA256SUMS`, открытый ключ — `packaging/minisign.pub` (устройство и ротация ключа — 11-build.md). Проверка подписи в приложении — #249; в окне её пока нет.

## Проверка

`roost::Updates` (`src/qml_api/updates.hpp`, `Roost.updates`) живёт в окне, не в `roostd`. Первая проверка идёт, когда окно подключилось и прочитало документ `settings`; дальше таймер каждые 24 часа. Запрос — `GET https://api.github.com/repos/zexUlt/roost/releases/latest` через `QNetworkAccessManager` (`Accept: application/vnd.github+json`, `User-Agent: roost/<версия>`), таймаут передачи 30 с, повторов нет: следующая попытка — по таймеру. Второе окно проверяет само.

- `html_url` предлагается, только если начинается с `https://github.com/zexUlt/roost/releases/`: ссылку открывает система, а ответ пришёл из сети. Иная ссылка (`file:`, чужой хост) — сбой с причиной `the answer has a release page outside the repository`, ничего не показывается.
- Из ответа берутся `tag_name` (`vX.Y.Z`), `html_url` и `assets[]` (`name`, `browser_download_url`: для скачивания). Версии сравниваются числами по частям (`0.10.0` новее `0.9.0`), а не текстом; версия окна — начало `VersionString()` (`src/core/version.hpp`). Тег не вида `vX.Y.Z` (суффикс, две части, нет `v`) не предлагается и не ошибка. Предлагается только версия новее версии окна; `draft: true` и `prerelease: true` не предлагаются.
- Сбой (ошибка сети, HTTP не 200, ответ не объект JSON, нет строк `tag_name` и `html_url`) ничего не показывает и пишется в лог одной строкой `qWarning` на причину: пока та же причина повторяется, строка не повторяется; хороший ответ сбрасывает счёт. Причина — `HTTP <код>`, `network error: <текст Qt>`, `the answer is not a JSON object`, `the answer has no tag_name and html_url`, `the answer has a release page outside the repository`.
- HTTPS идёт через TLS-бэкенд Qt: в AppImage `usr/plugins/tls/libqopensslbackend.so` (libssl3 он берёт из системы во время работы), в `.app` `Contents/PlugIns/tls/libqsecuretransportbackend.dylib` (TLS системы). Оба файла проверяют `tools/check_appimage.sh` и `tools/check_bundle.sh` (11-build.md). Без бэкенда проверка — сбой `network error`.
- Адрес запроса для тестов подменяет переменная окружения `ROOST_TEST_UPDATES_URL`; в работе её не задают. Пустая, но заданная — запросов нет вообще: так её ставят бинарники тестов (`tests/helpers/test_environment.cpp`), чтобы ни один тест не ходил в GitHub. Только для тестов и две другие переменные, которые читаются, лишь пока `ROOST_TEST_UPDATES_URL` задана и не пуста: `ROOST_TEST_UPDATES_PUBLIC_KEY` — текст `minisign.pub`, которым проверяется подпись вместо встроенного ключа (тестовые файлы подписаны ключом тестов, не релизным), и адрес файлов релиза, который берётся от адреса проверки (`<схема и хост из ROOST_TEST_UPDATES_URL>/releases/download/<тег>/`). `ROOST_CACHE` — каталог кеша вместо кеша пользователя, как `ROOST_CONFIG` для состояния; тесты скачивания задают его своим временным каталогом.

## Скачивание и проверка

`Roost.updates.download()` скачивает и проверяет пакет релиза, который предложила проверка; код — `UpdateDownload` (`src/qml_api/update_download.{hpp,cpp}`, принадлежит `Updates`), сама проверка — чистые функции без сети в `src/core/update_verify.{hpp,cpp}`. Кнопки в окне пока нет: свойства и сигнал нужны установщикам (#250, #251), они же вызовут `download()`.

Что качается: пакет этой платформы и этой архитектуры плюс `SHA256SUMS` и `SHA256SUMS.minisig` того же релиза. Имя пакета — `packageAssetName`: macOS — `roost-<версия>-macos-<arch>.dmg` (`arch` — `QSysInfo::buildCpuArchitecture()`, то есть `uname -m` сборки: `arm64` или `x86_64`, как в `tools/package_macos.sh`), Linux — `roost-x86_64.AppImage` или `roost-aarch64.AppImage`. На другой системе (или Linux другой архитектуры) `canDownload` — `false`, `download()` ничего не делает.

- Адрес каждого из трёх файлов — `browser_download_url` из ответа проверки и должен начинаться с `https://github.com/zexUlt/roost/releases/download/<тег>/`, дальше одно имя файла: без `/`, `\`, `?`, `#` и `%` (путь вверх, запрос, экранирование не проходят). Иной адрес, как и релиз без одного из файлов, — сбой до первого запроса (`the release has <имя> at an address outside the repository`, `the release has no file <имя>`). Переходы на хранилище GitHub (`objects.githubusercontent.com`) выполняет Qt по своей безопасной политике (`NoLessSafeRedirectPolicy`: с HTTPS на HTTP не идёт).
- Файлы пишутся потоком, пакет целиком в памяти не держится. Пределы: `SHA256SUMS` 1 МиБ, подпись 16 КиБ, пакет 1 ГиБ (по `Content-Length` и по принятым байтам); таймаут передачи 30 с (отсутствие данных), повторов нет.
- Каталог попытки — `download-XXXXXX` в `<кеш>/updates/` (`ROOST_CACHE`, иначе `QStandardPaths::CacheLocation`: `~/Library/Caches/roost` на macOS, `~/.cache/roost` на Linux). Одна попытка — один новый каталог. Каталог попытки, оставшийся от аварийного выхода и старше суток, чистится при следующем старте. Скачивание одно: `download()` при идущем или готовом — ничего (готовый пакет не качается заново); при упавшем — новая попытка.
- Порядок: `SHA256SUMS`, подпись, затем проверка подписи и поиск строки пакета, и только потом пакет: пакет не качается, если подпись или строка не прошли. После пакета — SHA-256 файла (`QCryptographicHash`, потоком) против строки.
- Подпись — minisign, ключ в приложении — `packaging/minisign.pub` (CMake читает файл и вкомпилирует строку ключа, `src/qml_api/CMakeLists.txt`; тот же файл у релизного workflow, #248). Проверяет Monocypher (`third_party/monocypher`, 10-licenses.md): Ed25519 с SHA-512 (`monocypher-ed25519`). Формат `ED` — Ed25519 над BLAKE2b-512 файла (по умолчанию у minisign), `Ed` — над самим файлом (старый); оба принимаются. Порядок проверки: идентификатор ключа в подписи совпадает с ключом; подпись `SHA256SUMS`; подпись доверенного комментария (над подписью и текстом комментария); комментарий ровно `roost <тег> SHA256SUMS`, чужого релиза файлы не проходят. Строка пакета в `SHA256SUMS` (`<64 hex>  <имя>` или `<64 hex> *<имя>`, имя целиком) должна быть одна: нет строки, две строки или строка, которая не строка контрольной суммы, — сбой.
- Любой сбой или несовпадение: каталог попытки удаляется, ничего не остаётся, причина — одной строкой в `downloadError` и в журнале (`roost: the download of the update failed: <причина>`).

Интерфейс (`Roost.updates`): `canDownload` — есть предложение и пакет для этой платформы; `downloadState` — `""` (ничего), `"downloading"`, `"ready"`, `"failed"`; `downloadProgress` — доля пакета, 0..1 (пока размер неизвестен, 0); `downloadError` — причина сбоя. Только C++: `downloadedPackage()` — путь проверенного пакета в состоянии `ready` (иначе пустая строка) и сигнал `packageReady(QString path)`. Каталог живёт, пока живо окно, до следующего скачивания и до отмены: установщик использует пакет, не дожидаясь выхода окна.

Отмена: новое предложение (вышла версия новее или та же перестала предлагаться) и `updates.check: false` отменяют идущее скачивание (и сбрасывают готовое) и удаляют каталог; тот же релиз при повторной проверке скачивание не трогает.

## Замена AppImage

`src/core/appimage_install.{hpp,cpp}`, без GUI. `AppImagePath` решает, откуда запущен процесс: `$APPIMAGE` — существующий файл, `$APPDIR` задан, а каталог исполняемого файла внутри него (как в `DaemonLauncher`: `APPIMAGE` из окружения другого приложения не считается). Распакованный AppDir (нет `APPIMAGE`) и дерево `cmake --install` — «не AppImage», замены нет. `RunningAppImagePath` берёт окружение и каталог текущего процесса.

`ReplaceAppImage(appImage, package, digest)`: ещё раз сверяет SHA-256 пакета с `digest` (файл лежал в кеше), копирует его во временный файл рядом с AppImage (тот же раздел, поэтому `rename` атомарен), делает `fsync`, ставит права AppImage плюс `0755` и переименовывает поверх. В сам AppImage не пишет никогда: запущенный процесс держит его отображённым в память, а старый inode остаётся жить, пока его не отпустят. Симлинк разворачивается: заменяется файл, на который он указывает, ссылка остаётся (ссылка в `~/bin` должна продолжать работать); битая ссылка — как отсутствующий AppImage.

Любая ошибка оставляет AppImage нетронутым и удаляет временный файл; текст называет путь и причину. Каталог без права записи (или только для чтения): в тексте путь каталога и ручные шаги — скачать AppImage со страницы релиза и заменить файл самому.

Функции подключит к кнопке «Install and restart» то изменение, которое добавляет саму кнопку (#250); пока их никто не вызывает. Тесты: `tests/core/appimage_install_test.cpp` — настоящие файлы во временных каталогах (успех, не тот дайджест при установке, каталог без записи, нет пакета, нет AppImage, симлинк, определение AppImage по окружению).

## Настройка

`settings.updates.check` (05-plugins.md, общий раздел настроек): булево, по умолчанию `true`. `false` отменяет идущий запрос и снимает таймер; запросов нет, пока ключ `false`. Правка `settings` действует в окне сразу (`store.changed`): `true` запускает проверку сразу. Документ `settings`, который не прочитался при подключении, — как пустой: проверка включена, как по умолчанию (тема остаётся как есть). Не булево значение ключа и не объект в `updates` — значение по умолчанию (проверка включена), строка в журнал и строка в полосе проблем: `settings.updates.check must be true or false; the check is on`, `settings.updates must be an object with check; the check is on` (как проблемы шрифтов, `Roost.updates.problems`).

## Строка в окне

`Roost.updates` (только чтение): `available` — версия без `v` или пустая строка, `url` — страница релиза, `enabled` — проверка включена, `problems` — проблемы настройки; один сигнал `changed`. `Main.qml` показывает строку `updateStrip` между раскладкой и полосой проблем: `roost v<версия> is out`, кнопка «Release page» (`Qt.openUrlExternally(url)`) и «Dismiss». Это предложение, а не проблема: цвета — токены `controlBackground` и `windowText`, в `shownProblems` её нет. Строка одна на версию.

Dismiss прячет предложение, пока не выйдет версия новее отклонённой. Отклонённая версия лежит в документе окна `updates` (`updates.json`, 08-state.md): `{"dismissed": "X.Y.Z"}`, пишется одним `store.patch`. Пока документ не прочитан, строки нет: отклонённая версия не мелькает при старте. Окна следят за документом (`store.changed`), поэтому отказ в одном окне прячет строку и в другом. Не прочитался документ — как пустой.

## Окно настроек

Общий раздел: переключатель «Check for updates» пишет `updates.check` одним `store.patch` одного ключа (`{updates: {check: false}}`), как поля шрифтов; не удалась запись — переключатель возвращается к хранимому значению, причина под полями.
