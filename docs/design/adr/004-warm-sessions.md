# ADR 004: тёплые сессии в демоне и в окне, снимок при открытии канала

**Контекст.** Холодный `claude attach` — 133–155 мс до полного кадра в лучшем случае, до 922 мс в первом прогоне (prior-art §1.3). Стек UI на это не влияет. Состояние экрана обязано пережить перезапуск окна (§2).

**Решение.** `roostd` держит N attach открытыми и хранит экран каждого в libghostty-vt. Окно держит свой терминал на каждую тёплую сессию и кормит его потоком в фоне. Бинарный снимок передаётся при открытии канала сессии; окно открывает канал один раз на сессию, а не на каждое переключение (§3, §4).

**Альтернативы.**

| Вариант | Почему отказ |
|---|---|
| attach при каждом переключении | 130–155 мс на переход, нарушает §1 |
| держать attach ко всем сессиям | 59–126 МБ RSS на attach; при 13 сессиях до 1,6 ГБ сверх самих агентов |
| терминал только в демоне, снимок на каждое переключение | связка окна и демона по формату снимка срабатывает на каждом переходе, а не изредка |
| терминал только в окне | состояние экрана умирает вместе с окном, нарушает инвариант §2 |
| проиграть окну весь вывод с начала attach | объём не ограничен |
| попросить TUI перерисоваться (resize, Ctrl-L) | зависит от агента, теряет scrollback, экран мигает |
| снимок как VT-поток через formatter | не зависит от формата снимка, но полнота восстановления (режимы, scrollback) не проверена; при расхождении версий проще перезапустить демон (§4) |

**Последствия.** Разбор вывода дважды. Окно и демон собираются с одним тегом libghostty-vt. Память растёт линейно с N в обоих процессах.
