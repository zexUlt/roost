# ADR 013: нативные плагины через C ABI

**Контекст.** Пользователям нужны нативные плагины на C++ наравне со встроенными. Классы C++ и типы Qt на границе привязали бы плагин к компилятору, стандартной библиотеке и размещению полей в классах roost: OBS сохранил C API, но в 28.0 «certain plugins that depend on version 5 of Qt will no longer work» (https://github.com/obsproject/obs-studio/releases/tag/28.0.0), а C++-плагин QGIS, собранный под одну версию, «is unlikely to work with other versions» (https://www.gispo.fi/en/blog/c-plugins-in-qgis/).

**Решение.** Обещание roost — C ABI: заголовок `roost/plugin.h`, таблицы со `struct_size`, которые только дописываются, рукопожатие по версии SDK и Qt, вызовы по именам методов каталога §4. Свои QML-типы плагин отдаёт стандартным QML-модулем, и там действует гарантия Qt, а не roost. Нативный код грузится только в окне и не выгружается. Один слой `src/api/` в окне обслуживает `Roost.*` и SDK, а имена методов у них общие с каталогом §4. SDK 0.x помечен нестабильным, 1.0 — по критерию §5.

**Альтернативы.**

| Вариант | Почему отказ |
|---|---|
| C++ SDK с типами Qt и pimpl | гарантия не шире гарантии Qt и размещения полей в классах roost; любая правка класса — риск ABI |
| `QPluginLoader` для всех | плагину без Qt пришлось бы тянуть moc и `Q_PLUGIN_METADATA` |
| только QML и бэкенды | нет нативных панелей и моделей со скоростью C++ |

**Последствия.** Вызовы через C ABI строковые по имени метода; типизацию даёт C++-обёртка. Кодировка данных выбирается замером в M6 и объявлена в рукопожатии, поэтому её смена не ломает ABI. Падение нативного плагина роняет окно; тёплые сессии и состояние переживают это в `roostd`. В CI появляются `abidiff`, тест раскладки и фикстуры старого SDK. Подписанный `.app` грузит чужие библиотеки только с `disable-library-validation`.
