# ADR 005: плагин — QML и бэкенд-процесс

**Контекст.** Плагину нужны свой UI и своя логика. UI должен грузиться без компиляции, логика не должна блокировать GUI-поток.

**Решение.** UI — QML с диска. Логика — JavaScript в QML для лёгкого и отдельный процесс с JSON-RPC по stdio для тяжёлого. Нативный код — через SDK с C ABI (ADR 013).

**Альтернативы.**

| Вариант | Почему отказ |
|---|---|
| нативные C++-плагины через `QPluginLoader` для всех | привязаны к версии Qt и компилятору; стороннему автору пришлось бы собирать под каждую сборку roost. Нативный код — через C ABI, а привязка к Qt остаётся только у QML-модуля плагина (ADR 013) |
| WASM-модули (как у Zed) | своего UI у них нет, пришлось бы изобретать протокол описания панелей |
| Lua (как sheprd) | второй скриптовый язык рядом с QML JavaScript без выигрыша |

**Последствия.** Два места исполнения кода плагина. Бэкенд-процесс стоит памяти, поэтому он необязателен.
