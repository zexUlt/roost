# 1. Цели и границы

Четыре цели, в порядке приоритета:

1. Отзывчивость. Список сессий, хоткеи и панели не теряют кадров, пока терминалы льют вывод. Переход к недавней сессии — один кадр.
2. Плагины со старта. Каждая фича, включая встроенные, — плагин на публичном API, и её можно заменить целиком. Плагин пишется на QML, на любом языке как бэкенд-процесс или на C/C++ через SDK с C ABI, который становится стабильным с SDK 1.0 (§5).
3. Модульный UI. Плагины добавляют панели; пользователь расставляет их и связывает выходы одной панели со входами другой.
4. Модульные агенты. Сначала Claude Code, потом Codex, OpenCode и агенты по ACP через тот же интерфейс адаптера.

Критерий готовности v1 одной строкой: **все фоновые сессии Claude видны без ручных действий, переход к тёплой сессии укладывается в кадр, а список отвечает на хоткеи, пока соседний терминал льёт 1 МБ/с.**

Не-цели v1, названные явно: песочница для плагинов, визуальный редактор связей, Windows, заморозка API плагинов до SDK 1.0 (§5), свой чат поверх SDK агента.

Агенты работают на той же машине, что и окно: на Linux это рабочий стол с AppImage. Агенты на удалённой машине, например на dev-VM по ssh, требуют удалённого `roostd`; их поддержка запланирована после M7 (§13).
