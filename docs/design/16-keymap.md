# 16. Хоткеи

Клавиши назначают два источника: вклады `keybindings` в манифестах плагинов (§5) и файл пользователя `keymap.json` в каталоге состояния (§8). Файл сильнее вкладов; без файла действуют одни вклады.

## Файл пользователя

```json
[
  { "key": "Ctrl+Shift+N", "mac": "Cmd+N", "command": "claude.newSession" },
  { "key": "Ctrl+Shift+M", "mac": "Cmd+Shift+N", "command": "claude.newSession", "args": { "category": "work" } },
  { "key": "J", "command": "sessions.next", "when": "sessions.list" },
  { "mac": "Cmd+W", "command": null }
]
```

- Массив записей `{key?, mac?, command, args?, when?}`, хотя бы одна из `key` и `mac`. `command` — id команды из вкладов, `args` уходит в команду как есть.
- `mac` заменяет `key` на macOS. Запись только с `mac` на Linux не действует; запись только с `key` действует на обеих платформах. Каталог конфига бывает общим для мака и Linux, поэтому одна запись описывает обе.
- `when` — тип панели, у которой фокус (`sessions.list`, `claude.transcript`). Без `when` клавиша действует в любой панели. Так буквы работают в списке, а `Ctrl+\` — отовсюду, как в cc-fleet (`src/cc_fleet/app.py:77`, `:1222`). `Ctrl+\` («фокус в список») есть с шага 7 как оконный `Shortcut`, вшитый в `src/roost/Main.qml`; с раскладкой клавиш (M5) он становится записью по умолчанию, которую пользователь переопределяет в `keymap.json`.
- `command: null` снимает клавишу с тем же `when`: и у вкладов, и у записей файла выше неё. Записи с другим `when` она не трогает: чтобы снять клавишу вклада в панели, `when` пишется тот же, что у вклада.
- roost файл не создаёт и не переписывает, правит его только пользователь. Id плагина `keymap` зарезервирован: иначе файл состояния плагина `<id>.json` (§8) совпал бы с файлом хоткеев.

## Разрешение

Таблица ключуется парой (клавиша, `when`). Внутри пары действует одна запись:

1. Нижняя запись файла, как в `keybindings.json` VS Code (https://code.visualstudio.com/docs/configure/keybindings).
2. Иначе — вклад первого по порядку загрузки плагина (§5). Проигравший вклад — проблема. Вклад, перекрытый файлом, проблемой не считается, палитра показывает его как переопределённый.

На нажатие сначала ищется пара с `when` панели в фокусе, затем пара без `when`. Поэтому запись пользователя без `when` не перекрывает вклад с `when` в его панели: для этого пишется запись с тем же `when`. Сейчас реестр ключует клавиши одной клавишей (`Keys_`, `src/roostd/manifest.cpp:359`), и два вклада `J` в разных панелях выглядят для него конфликтом; ключ становится парой.

## Клавиша

- Запись — модификаторы через `+`, затем одна клавиша: `Cmd+Shift+N`, `Ctrl+\`, `Alt+Left`, `F5`, `J`. Модификаторы: `Ctrl`, `Alt` (Option на macOS), `Shift`, `Cmd` (только macOS). Регистр и порядок модификаторов не важны.
- `Cmd` в клавише, которая действует на Linux, — проблема записи. Super на Linux занят рабочим столом, и приложение нажатие часто не получает; поэтому `Cmd` пишется в `mac`.
- Имя модификатора значит физическую клавишу. `QKeySequence` для разбора не подходит: в Qt `Key_Control` на macOS — это ⌘, а `Key_Meta` — Control (https://doc.qt.io/qt-6/qt.html#Key-enum), и `Ctrl+N` из конфига сработал бы на ⌘N. Тот же сдвиг уже учитывает `IsCopyShortcut` (`src/terminal/qt_key_mapping.hpp:67-72`).
- Клавиши сравниваются в разобранном виде: набор модификаторов и код клавиши. Реестр сейчас сравнивает текст в нижнем регистре (`src/roostd/manifest.cpp:359`), и `Shift+Ctrl+N` для него не совпадает с `Ctrl+Shift+N`; разбор это исправляет.
- Буква сопоставляется по символу текущей раскладки, если раскладка латинская, иначе по физическому положению на раскладке US. `Cmd+Z` на Dvorak остаётся на клавише с буквой Z, а `J` срабатывает и на русской раскладке, как в cc-fleet (`README.md:51`). Положение берётся из нативного скан-кода, которое `MapQtKey` пока не читает (`src/terminal/qt_key_mapping.hpp:54-62`).
- Последовательностей вида `Cmd+K Cmd+S` в v1 нет: у cc-fleet их нет, а ожидание второго нажатия задерживает первое.

## Ввод текста

- Когда фокус в терминале или в поле ввода, нажатие сначала ищется в таблице, и только непойманное уходит в PTY или в поле. Пойманная клавиша у программы и у поля отбирается.
- Поэтому клавиша без `Cmd`, `Ctrl` и `Alt`, кроме F1–F24, в терминале и в поле ввода не срабатывает ни с каким `when`. Без `when` она — проблема записи: действовать ей негде, кроме панелей без ввода, а там её место — `when` этой панели.
- `Ctrl` с буквой в терминале — управляющий символ для программы, `Alt` с буквой на macOS набирает символ. Такие клавиши срабатывают, но палитра помечает их как «перехватывает ввод».
- Пока метод ввода (IME) собирает символ, таблица не просматривается: нажатие принадлежит IME.

## Вклады плагинов

- Вклад — та же запись без `args`, с обязательной `command`: `{ "command": "claude.newSession", "key": "Ctrl+Shift+N", "mac": "Cmd+N" }`. Ключ `mac` взят у `contributes.keybindings` VS Code (https://code.visualstudio.com/api/references/contribution-points).
- Неразборная клавиша во вкладе — проблема: вклад не действует, остальной манифест грузится. Сейчас `ParseKeybindings` отвергает весь манифест (`src/roostd/manifest.cpp:104-131`); разбор клавиши переезжает в реестр, и разбор манифеста на ней больше не падает.

## Кто читает и кто исполняет

- Файл читает `roostd`: у него уже есть реестр вкладов с конфликтами (`src/roostd/manifest.cpp:318-383`) и каталог состояния (§8). Окно запрашивает таблицу методом `keymap.get {platform}`, а после правки файла получает событие `keymap.changed` (§4). Платформу называет окно: демон может работать на другой машине (§14).
- Запись итоговой таблицы — `{key, command, args?, when?, source}`, где `key` уже приведён к платформе окна, а `source` — `user` или id плагина. Окно сопоставляет нажатие с таблицей в GUI-потоке поиском по хешу и файлов не читает. Таблица, которая не помещается в кадр, — `InternalError`, как у `sessions.list`.
- Нажатие обрабатывает окно, у которого фокус; `keymap.changed` приходит всем окнам. Команду окно запускает так же, как палитра. Как исполняется команда без бэкенда (копирование, шаг по списку), открытый вопрос (§14). До ответа копирование остаётся в `TerminalItem` (`IsCopyShortcut`).
- Изменения отслеживает `QFileSystemWatcher` на файле и на каталоге. После `rename` Qt перестаёт следить за файлом (https://doc.qt.io/qt-6/qfilesystemwatcher.html), а редактор, который сохраняет через временный файл, делает именно `rename`; событие каталога возвращает файл под слежение. Файл перечитывается через 100 мс после последнего события, чтобы не разбирать его посреди записи.
- Файл не JSON, не массив или больше 1 МиБ: действует прежняя таблица, и проблема видна пользователю. Это исключение из правила §8 «неразборный файл — ошибка»: файл правят руками, и опечатка не должна сбрасывать клавиши. При старте прежней таблицы нет, тогда действуют одни вклады. Битая запись (неразборная клавиша, неизвестная команда, `when` не строкой, клавиша без модификатора и без `when`, `Cmd` на Linux) пропускается с проблемой, остальные действуют.

Цена: JSON без комментариев, `QJsonDocument` их не принимает. Пояснить запись или временно закомментировать её нельзя; чтобы временно снять клавишу, запись удаляют. Альтернативы и причины отказа — ADR 014.
