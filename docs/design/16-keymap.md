# 16. Хоткеи

Клавиши назначают два источника: вклады `keybindings` в манифестах плагинов (§5) и файл пользователя `keymap.json` в каталоге состояния (§8). Файл сильнее вкладов; без файла действуют одни вклады.

## Файл пользователя

```json
[
  { "key": "Cmd+N", "command": "claude.newSession" },
  { "key": "Cmd+Shift+N", "command": "claude.newSession", "args": { "category": "work" } },
  { "key": "J", "command": "sessions.next", "when": "sessions.list" },
  { "key": "Ctrl+Shift+N", "mac": "Cmd+Alt+N", "command": "claude.newSession" },
  { "key": "Cmd+W", "command": null }
]
```

- Массив записей `{key, mac?, command, args?, when?}`. `command` — id команды из вкладов, `args` уходит в `commands.run` как есть.
- `mac` заменяет `key` на macOS. Каталог конфига бывает общим для мака и Linux, поэтому одна запись описывает обе платформы.
- `command: null` снимает клавишу со всех вкладов: в контексте `when`, а без `when` — везде.
- `when` — тип панели, у которой фокус (`sessions.list`, `claude.transcript`). Без `when` клавиша действует везде; запись с `when` панели в фокусе сильнее записи без него. Так буквы работают в списке, а `Ctrl+\` — отовсюду, как в cc-fleet (`src/cc_fleet/app.py:77`, `:1222`).
- Две записи файла с одной клавишей и одним `when`: действует нижняя, как в `keybindings.json` VS Code (https://code.visualstudio.com/docs/configure/keybindings). Это осознанное переопределение, а не проблема.
- roost файл не создаёт и не переписывает, правит его только пользователь. Id плагина `keymap` зарезервирован: иначе файл состояния плагина `<id>.json` (§8) совпал бы с файлом хоткеев.

## Клавиша

- Запись — модификаторы через `+`, затем одна клавиша: `Cmd+Shift+N`, `Ctrl+\`, `Alt+Left`, `F5`, `J`. Модификаторы: `Ctrl`, `Alt` (Option на macOS), `Shift`, `Cmd` (⌘ на macOS, Super на Linux). Регистр и порядок модификаторов не важны.
- Имя модификатора значит физическую клавишу на любой платформе. `QKeySequence` для разбора не подходит: в Qt `Key_Control` на macOS — это ⌘, а `Key_Meta` — Control (https://doc.qt.io/qt-6/qt.html#Key-enum), и `Ctrl+N` из конфига сработал бы на ⌘N. Тот же сдвиг уже учитывает `IsCopyShortcut` (`src/terminal/qt_key_mapping.hpp:67-72`).
- Клавиши сравниваются в разобранном виде: набор модификаторов и код клавиши. Реестр вкладов сейчас сравнивает текст в нижнем регистре (`src/roostd/manifest.cpp:359`), и `Shift+Ctrl+N` для него не совпадает с `Ctrl+Shift+N`; разбор это исправляет.
- Буквы, цифры и знаки сопоставляются по физическому положению на раскладке US: `J` срабатывает и на русской раскладке, как в cc-fleet (`README.md:51`). Для этого нужно сопоставление по нативному скан-коду, которое `MapQtKey` пока откладывает (`src/terminal/qt_key_mapping.hpp:54-62`).
- Последовательностей вида `Cmd+K Cmd+S` в v1 нет: у cc-fleet их нет, а ожидание второго нажатия задерживает первое.

## Вклады плагинов

- Вклад — та же запись без `args`: `{ "command": "claude.newSession", "key": "Ctrl+Shift+N", "mac": "Cmd+N", "when"?: ... }`. Ключ `mac` взят у `contributes.keybindings` VS Code (https://code.visualstudio.com/api/references/contribution-points).
- Неразборная клавиша во вкладе — проблема загрузки: вклад не действует, остальной манифест грузится.
- Порядок разрешения: файл пользователя, затем вклады в порядке загрузки (§5). Проигравший вклад — проблема; вклад, переопределённый файлом, — нет, палитра показывает его как переопределённый.

## Терминал

- В фокусе терминала нажатие сначала ищется в keymap, и только непойманное уходит в PTY. Клавиша без `when` отбирается у программы в терминале.
- Поэтому клавиша без `when` содержит `Cmd`, `Ctrl` или `Alt`, кроме F1–F24. Запись с одной буквой, Enter, Tab, Escape или стрелкой без `when` — проблема, и она не действует: иначе она съела бы набор текста во всех панелях.
- `Ctrl` с буквой в терминале — управляющий символ для программы. Палитра помечает такие клавиши без `when` как «перехватывает у терминала».
- Копирование (`IsCopyShortcut`) переходит во вклады терминальной панели командой и переназначается так же, как остальные клавиши.

## Кто читает

- Файл читает `roostd`: у него уже есть реестр вкладов с конфликтами (`src/roostd/manifest.cpp:318-383`) и каталог состояния (§8). Демон сводит файл с вкладами и отдаёт окну итоговую таблицу: метод `keymap.get` и событие `keymap.changed` (§4).
- Запись итоговой таблицы — `{key, command, args?, when?, source}`, где `key` уже приведён к платформе, а `source` — `user` или id плагина. Окно сопоставляет нажатие с таблицей в GUI-потоке поиском по хешу и файлов не читает.
- Изменения отслеживает `QFileSystemWatcher` на файле и на каталоге. После `rename` Qt перестаёт следить за файлом (https://doc.qt.io/qt-6/qfilesystemwatcher.html), а редактор, который сохраняет через временный файл, делает именно `rename`; событие каталога возвращает файл под слежение.
- Файл не JSON или не массив: действует прежняя таблица, и проблема видна пользователю. При старте прежней таблицы нет, тогда действуют одни вклады. Битая запись (неразборная клавиша, неизвестная команда, `when` не строкой, клавиша без модификатора и без `when`) пропускается с проблемой, остальные действуют.

Цена: JSON без комментариев, `QJsonDocument` их не принимает. Пояснить запись или временно закомментировать её нельзя; чтобы временно снять клавишу, запись удаляют. Альтернативы и причины отказа — ADR 014.
